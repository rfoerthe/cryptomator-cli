# M6: Keychain – macOS-Keychain, Secret Service, `password store/forget` und `--store-password` – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `crypto` speichert Vault-Passphrasen in denselben Keychain-Einträgen wie die Desktop-App und liest sie von dort: `crypto password store|forget <VAULT>`, `crypto unlock --store-password`, `crypto vault create --store-password`, `crypto vault remove --forget-password`, ein impliziter Keychain-Unlock (wenn `useKeychain` gesetzt und ein Eintrag vorhanden ist), die explizite Quelle `--password-keychain`, der globale Schalter `--no-keychain` und die Selbstdiagnose `crypto keychain test`. Backends: macOS-Login-Keychain über `security-framework`, FreeDesktop Secret Service über `secret-service`; KWallet meldet „nicht unterstützt“ mit Hinweis.

**Architecture:** Vier Schichten. (1) `cryptomator-app::keychain::mod` – das Trait `Keychain` (Java-`KeychainAccessProvider` eins zu eins), der Fehlertyp `KeychainError`, die Provider-Registry über Java-Klassennamen samt Aliassen und Prioritäten, `for_settings(&SettingsJson)` als Rust-Fassung von Javas `KeychainModule`, und `with_timeout` – **jeder** Keychain-Aufruf läuft in einem eigenen Thread mit 30-Sekunden-`recv_timeout`, damit ein hängender macOS-ACL-Dialog (Spike B) das CLI nicht einfriert. (2) Die Backends `keychain::macos` (`security-framework`, Generic Password, Service `"Cryptomator"`, Account = Vault-ID), `keychain::linux` (`secret-service` **blocking**, Attribute `{"Vault", "Name"}`) und `keychain::kde` (Stub). (3) `keychain::fake` – ein dateigestützter Fake, den `CRYPTO_KEYCHAIN_FAKE=<pfad>` einschaltet, sodass jeder CLI-Fluss auf jedem Betriebssystem ohne echte Keychain vollständig getestet wird. (4) `password.rs` + die Kommandos: die Quellenreihenfolge bekommt zwei Keychain-Stufen, `crypto password store|forget`, `keychain test` und die drei Flags an `unlock`/`vault create`/`vault remove`.

**Tech Stack:** Rust stable ≥ 1.89; `security-framework` 3.7.0 (macOS, MIT/Apache-2.0, `rust-version = 1.85`, Default-Features), `secret-service` 5.2.0 (Linux, MIT/Apache-2.0, `edition = "2024"`, `rust-version = 1.87.0`, Feature `rt-tokio-crypto-rust` → `zbus/tokio` + reines RustCrypto, kein OpenSSL) mit `zbus` 5.13.2 darunter; `getrandom` (Selbsttest-Schlüssel), `zeroize`, `serde_json` (Fake-Datei), `clap` 4.6, `assert_cmd` 2.

**Spec:** `docs/superpowers/specs/2026-09-04-crypto-cli-design.md` (Abschnitt `keychain/{mod,macos,linux}.rs`, Abschnitt `password.rs`, die Kommando-Grammatik zu `password change|store|forget`, `vault create --store-password`, `unlock --store-password|--no-store-password`, `vault remove --forget-password`, `keychain test`, `config`-Schlüssel `useKeychain`/`keychainProvider`, Exit-Code **8**, Crate-Tabelle „Keychain“, Meilenstein **M6**, Teststrategie-Zeile „Keychain-E2E“, Risiko 2, Entscheidung 2, Entscheidung 10, Fußnoten `[^m4-scope]` und `[^m5-scope]`) und `docs/superpowers/spikes/2026-09-04-spike-b-keychain.md`.

- Rulings dieses Meilensteins (im Code kommentieren, in Task 10 dokumentieren):
  1. **Timeout um jeden Aufruf.** `with_timeout(30 s)` = Worker-Thread + `mpsc::sync_channel(1)` + `recv_timeout`. Läuft die Zeit ab, meldet das CLI Exit **8** mit dem Text „the keychain did not answer within 30 s; a system dialog may be waiting for you“. Der Worker-Thread wird **nicht** abgebrochen (das kann man nicht) – er hängt in `securityd` und stirbt mit dem Prozess. Deshalb ist `Keychain: Send + Sync + 'static` und alle Backends sind zustandslos.
  2. **Quellenreihenfolge** (endgültig): `--password-stdin` → `--password-file` → `--password-env VAR` → `$CRYPTO_PASSWORD` → `--password-keychain` (**explizit**: fehlt der Eintrag, ist das Exit 8, kein Weiterfallen) → **implizite** Keychain (nur wenn `useKeychain` **und** ein Provider unterstützt **und** kein `--no-keychain` **und** ein Eintrag da ist; fehlt der Eintrag, fällt es stillschweigend weiter) → TTY-Prompt → sonst Exit 4… nein: `AppError::NoPasswordSource` → Exit **2** wie bisher. `$CRYPTO_PASSWORD` steht bewusst **über** `--password-keychain`: die Variable ist die maschinenfreundliche Quelle und gewinnt gegen eine, die einen Dialog auslösen kann. Das ist zu dokumentieren.
  3. **Nie implizit speichern.** Anders als der „Passwort speichern“-Haken der Desktop-App speichert das CLI nur auf ausdrückliche Anweisung: `--store-password` bzw. `password store`. `--no-store-password` existiert trotzdem, damit ein Skript den Standard explizit machen kann.
  4. **`password store` verifiziert vorher.** Die Passphrase wird gegen `masterkey.cryptomator` geprüft (`open_vault`), bevor sie in die Keychain geht – eine falsche gespeicherte Passphrase wäre schlimmer als gar keine.
  5. **Jeder Passwortwechsel aktualisiert einen vorhandenen Eintrag immer** – `password change` **und** `recovery-key reset-password`, denn beide schreiben die Masterkey-Datei neu. Wie Javas `KeychainManager.changePassphrase`: existiert ein Eintrag, wird er auf die neue Passphrase gesetzt; existiert keiner, passiert nichts. Es gibt kein `--keep-keychain`. Schlägt das Aktualisieren fehl, ist das eine **Warnung auf stderr** und kein Fehler – die Passphrase auf der Platte ist bereits geändert, und Exit ≠ 0 würde ein Skript zu einem falschen Rollback verleiten.
  6. **Kein eigener Touch-ID-Provider.** `TouchIdKeychainAccess` in `settings.json` wird auf das macOS-Backend abgebildet (gleicher Service, gleicher Account – es sind dieselben Items). Lesen und Löschen funktionieren; neu geschriebene Items haben **keine** Touch-ID-Zugriffskontrolle. Dokumentierte Abweichung („best effort“).
  7. **KWallet ist unsupported.** `KDEWalletKeychainAccess` gibt es als Stub, damit ein `settings.json` mit diesem Wert nicht zum harten Fehler wird; `is_supported()` ist `false`, jeder Aufruf liefert `KeychainError::Unsupported` mit dem Hinweis, auf `secret-service` umzustellen.
  8. **Der Fake ist eine Datei, kein Feature.** `CRYPTO_KEYCHAIN_FAKE=<pfad>` schaltet ihn ein, in Debug- **und** Release-Builds, weil die CLI-Tests gegen das gebaute Binary laufen. Er ist dadurch auch ein Debug-Werkzeug. Ist die Variable gesetzt, ist der Fake der **einzige** unterstützte Provider – kein Test kann versehentlich die echte Keychain treffen.
- Bekannte, in M6 **nicht** gelöste Punkte (in CHANGELOG und README als Limitierung): Ein von Cryptomator.app geschriebener Eintrag löst beim ersten Lesen durch `crypto` einen macOS-ACL-Dialog aus, bis das Release-Binary mit einer stabilen Identität signiert ist (Spike B, Beobachtung 4/5 – „Immer erlauben“ im Dialog); Touch-ID-Einträge werden gelesen, aber nicht erzeugt; KWallet fehlt; `LinuxGioMounter` und macFUSE bleiben unverifiziert (aus M4/M5).

```rust
//! Vault passphrases in the operating system's keychain, compatible with the desktop app's
//! entries.
//!
//! The trait is `org.cryptomator.integrations.keychain.KeychainAccessProvider` (integrations-api
//! 1.9.0) with two Rust-shaped differences: `load` answers `Ok(None)` where Java answers `null`,
//! and `delete`/`change` answer "was there an entry?" as a `bool` -- which is what
//! `MacKeychain.deletePassword` already does and what `KeychainManager.changePassphrase` needs.
//!
//! **Every** call from the CLI goes through [`with_timeout`]. Spike B
//! (`docs/superpowers/spikes/2026-09-04-spike-b-keychain.md`) showed macOS blocking indefinitely
//! in an ACL dialog that a non-interactive session cannot answer; `SecItemCopyMatching` has no
//! timeout of its own, so the only way out is a worker thread the caller stops waiting for.
use crate::error::AppError;
use std::fmt;
use std::sync::mpsc;
use std::time::Duration;
use zeroize::Zeroizing;

#[cfg(target_os = "linux")]

#[cfg(target_os = "macos")]

/// How long the CLI waits for one keychain call. Long enough for a human to answer a dialog,
/// short enough that a headless run fails instead of hanging forever.
pub const KEYCHAIN_TIMEOUT: Duration = Duration::from_secs(30);

/// Overrides the macOS/Secret-Service service name, like the desktop app's system property
/// `cryptomator.integrationsMac.keychainServiceName`.

pub const MAC_TOUCH_ID_CLASS: &str = "org.cryptomator.macos.keychain.TouchIdKeychainAccess";
pub const SECRET_SERVICE_CLASS: &str =
    "org.cryptomator.linux.keychain.SecretServiceKeychainAccess";
pub const GNOME_KEYRING_CLASS: &str = "org.cryptomator.linux.keychain.GnomeKeyringKeychainAccess";
pub const KDE_WALLET_CLASS: &str = "org.cryptomator.linux.keychain.KDEWalletKeychainAccess";

/// Short names for `crypto config set keychainProvider`, in the order the error message lists
/// them. The stored value is always the Java class name, so the desktop app keeps reading its
/// own setting.
pub const KEYCHAIN_ALIASES: &[(&str, &str)] = &[
    ("macos", MAC_SYSTEM_CLASS),
    ("touchid", MAC_TOUCH_ID_CLASS),
    ("secret-service", SECRET_SERVICE_CLASS),
    ("gnome-keyring", GNOME_KEYRING_CLASS),
    ("kde", KDE_WALLET_CLASS),
    ("kwallet", KDE_WALLET_CLASS),

/// Alias (case-insensitive) or a fully qualified Java class name (must contain a dot).
///
/// # Errors
/// [`AppError::InvalidValue`] (exit code 2) for anything else.
pub fn resolve_keychain_provider(input: &str) -> Result<String, AppError> {
    let lowered = input.to_lowercase();
    if let Some((_, class)) = KEYCHAIN_ALIASES.iter().find(|(alias, _)| *alias == lowered) {
        return Ok((*class).to_string());
    }
    if input.contains('.') {
        return Ok(input.to_string());
    }
    Err(AppError::InvalidValue {
        key: "keychainProvider".to_string(),
        message: format!(
            "unknown keychain provider {input:?}; use one of {} or a Java class name",
            KEYCHAIN_ALIASES
                .iter()
                .map(|(alias, _)| *alias)
                .collect::<Vec<_>>()
                .join(", ")
        ),
    })
}

/// The first alias of `class_name`, for human-readable output. `kwallet` never wins over `kde`
/// because it comes later in [`KEYCHAIN_ALIASES`].
pub fn alias_for_keychain(class_name: &str) -> Option<&'static str> {
    KEYCHAIN_ALIASES
        .iter()
        .find(|(_, class)| *class == class_name)
        .map(|(alias, _)| *alias)
}

/// The service name (macOS) / item label (Secret Service). An empty override counts as unset:
/// an empty service matches no item, so it could only ever hide entries.
pub fn service_name() -> String {

        Ok(value) if !value.is_empty() => value,
        _ => DEFAULT_SERVICE.to_string(),

/// What a keychain backend can fail with. Never carries a passphrase.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum KeychainError {
    /// The backend cannot work on this machine (no Secret Service, KWallet, wrong OS).
    Unsupported { provider: String, hint: String },
    /// The keyring exists but is locked and nobody unlocked it.
    Locked { provider: String },
    /// The call did not answer within [`KEYCHAIN_TIMEOUT`] -- on macOS almost always an ACL
    /// dialog nobody is looking at.
    TimedOut { provider: String },
    /// Anything the backend itself reported.
    Backend { provider: String, message: String },
}

impl fmt::Display for KeychainError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Self::Unsupported { provider, hint } => {
                write!(f, "{provider} cannot be used here: {hint}")
            }
            Self::Locked { provider } => write!(
                f,
                "{provider} is locked; unlock the keyring and try again"
            ),
            Self::TimedOut { provider } => write!(
                f,
                "{provider} did not answer within {} s; a system dialog may be waiting for you \
                 (choose \"Always Allow\")",
                KEYCHAIN_TIMEOUT.as_secs()
            ),
            Self::Backend { provider, message } => write!(f, "{provider}: {message}"),
        }
    }
}

impl std::error::Error for KeychainError {}

impl KeychainError {
    /// The provider that failed, for the message the CLI prints.
    pub fn provider(&self) -> &str {
        match self {
            Self::Unsupported { provider, .. }
            | Self::Locked { provider }
            | Self::TimedOut { provider }
            | Self::Backend { provider, .. } => provider,
        }
    }
}

pub type KeychainResult<T> = std::result::Result<T, KeychainError>;

/// One vault passphrase store. `Sync` because [`with_timeout`] hands the call to another thread.
pub trait Keychain: Send + Sync + fmt::Debug {
    /// The name in `settings.json`'s `keychainProvider`.
    fn java_class_name(&self) -> &'static str;
    /// Javas `NamedServiceProvider.getName()`; a short, human-readable name.
    fn display_name(&self) -> &'static str;
    /// Javas `@Priority`; higher wins when `keychainProvider` names nothing usable.
    fn priority(&self) -> u32;
    /// Javas `isSupported()`: must not throw and must fail fast.
    fn is_supported(&self) -> bool;
    /// Javas `isLocked()`.
    fn is_locked(&self) -> bool;
    /// Javas `storePassphrase(key, displayName, passphrase)`; replaces an existing entry.
    fn store(&self, key: &str, display_name: Option<&str>, passphrase: &str) -> KeychainResult<()>;
    /// Javas `loadPassphrase(key)`; `Ok(None)` is Javas `null` -- nothing stored, not an error.
    fn load(&self, key: &str) -> KeychainResult<Option<Zeroizing<String>>>;
    /// Javas `deletePassphrase(key)`; `Ok(false)` when there was nothing to delete.
    fn delete(&self, key: &str) -> KeychainResult<bool>;
    /// Javas `changePassphrase(key, displayName, passphrase)`: "Noop, if there is no item for the
    /// given key". `Ok(false)` says it was that noop.
    fn change(
        &self,
        key: &str,
        display_name: Option<&str>,
        passphrase: &str,
    ) -> KeychainResult<bool>;
}

/// Runs `op` on a worker thread and gives up after [`KEYCHAIN_TIMEOUT`].
///
/// The worker is **not** cancelled on timeout -- a thread blocked in `securityd` or in a D-Bus
/// prompt cannot be. It keeps the channel's sender, notices nothing, and dies with the process.
/// That is why [`Keychain`] implementations are stateless and `Sync`: a leaked worker must not be
/// able to observe or corrupt anything the caller goes on to do.
pub fn with_timeout<T, F>(provider: &str, op: F) -> KeychainResult<T>
where
    T: Send + 'static,
    F: FnOnce() -> KeychainResult<T> + Send + 'static,
{
    with_timeout_for(provider, KEYCHAIN_TIMEOUT, op)
}

/// [`with_timeout`] with an explicit budget, so the tests do not have to wait 30 seconds.
pub fn with_timeout_for<T, F>(provider: &str, budget: Duration, op: F) -> KeychainResult<T>
where
    T: Send + 'static,
    F: FnOnce() -> KeychainResult<T> + Send + 'static,
{
    let (tx, rx) = mpsc::sync_channel::<KeychainResult<T>>(1);
    // `sync_channel(1)`: the worker never blocks on the send, so a late answer does not keep the
    // thread alive any longer than the call it was making.
    let spawned = std::thread::Builder::new()
        .name("keychain".to_string())
        .spawn(move || {
            let _ = tx.send(op());
        });
    if let Err(err) = spawned {
        return Err(KeychainError::Backend {
            provider: provider.to_string(),
            message: format!("cannot start the keychain worker: {err}"),
        });
    }
    match rx.recv_timeout(budget) {
        Ok(result) => result,
        Err(mpsc::RecvTimeoutError::Timeout) => Err(KeychainError::TimedOut {
            provider: provider.to_string(),
        }),
        // The worker panicked and dropped its sender.
        Err(mpsc::RecvTimeoutError::Disconnected) => Err(KeychainError::Backend {
            provider: provider.to_string(),
            message: "the keychain worker stopped unexpectedly".to_string(),
        }),
    }
}
```

```rust
//! `password store/forget`, `vault remove --forget-password`, `keychain test` -- is tested on
//! every operating system, in CI, without a real keyring, without a D-Bus session and without any
//! chance of a dialog. It is deliberately **not** behind `#[cfg(test)]`: the CLI tests run the
//! built binary, so the binary has to know it too.
//!
//! While the variable is set, this is the only provider the registry offers
//! (`keychain::all_providers`), so a test can never reach the user's real keychain by accident.
use super::{Keychain, KeychainError, KeychainResult};
use serde::{Deserialize, Serialize};
use std::collections::BTreeMap;
use std::io::Write;
use std::os::unix::fs::OpenOptionsExt;
use std::path::{Path, PathBuf};
use zeroize::Zeroizing;

/// Points at the JSON file that holds the fake entries.
pub const FAKE_ENV: &str = "CRYPTO_KEYCHAIN_FAKE";
/// Set to `1` to make the fake report `is_locked() == true` and fail every call with
/// [`KeychainError::Locked`].
pub const FAKE_LOCKED_ENV: &str = "CRYPTO_KEYCHAIN_FAKE_LOCKED";
/// Set to `1` to make the fake report `is_supported() == false`.
pub const FAKE_UNSUPPORTED_ENV: &str = "CRYPTO_KEYCHAIN_FAKE_UNSUPPORTED";
/// Its `keychainProvider` value; the prefix is ours, so it can never collide with a real one.
pub const FAKE_CLASS: &str = "org.cryptomator.cli.FakeKeychainAccess";
/// Its `getName()`.
const FAKE_DISPLAY_NAME: &str = "Fake keychain (file)";
/// Above every real provider, because while it is on it is the only one.
const FAKE_PRIORITY: u32 = 10_000;
/// The file holds passphrases in the clear.
const FILE_MODE: u32 = 0o600;

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
struct Entry {
    password: String,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    display_name: Option<String>,
}

/// `BTreeMap` rather than `HashMap`, so the file is stable across runs and a diff is readable.
type Entries = BTreeMap<String, Entry>;

#[derive(Debug, Clone)]
pub struct FakeKeychain {
    path: PathBuf,
}

impl FakeKeychain {
    /// The fake for `$CRYPTO_KEYCHAIN_FAKE`, or `None` when the variable is unset or empty.
    pub fn from_env() -> Option<Self> {
        match std::env::var(FAKE_ENV) {
            Ok(path) if !path.is_empty() => Some(Self::at(path)),
            _ => None,
        }
    }

    pub fn at(path: impl Into<PathBuf>) -> Self {
        Self { path: path.into() }
    }

    pub fn path(&self) -> &Path {
        &self.path
    }

    /// The display name stored next to `key`, for the tests that check what `store` wrote.
    pub fn display_name_of(&self, key: &str) -> KeychainResult<Option<String>> {
        Ok(self
            .read()?
            .get(key)
            .and_then(|entry| entry.display_name.clone()))
    }

    fn flag(name: &str) -> bool {
        std::env::var(name).is_ok_and(|value| value == "1")
    }

    fn guard(&self) -> KeychainResult<()> {
        if Self::flag(FAKE_UNSUPPORTED_ENV) {
            return Err(KeychainError::Unsupported {
                provider: FAKE_DISPLAY_NAME.to_string(),
                hint: format!("{FAKE_UNSUPPORTED_ENV} is set"),
            });
        }
        if Self::flag(FAKE_LOCKED_ENV) {
            return Err(KeychainError::Locked {
                provider: FAKE_DISPLAY_NAME.to_string(),
            });
        }
        Ok(())
    }

    fn failed(&self, message: impl std::fmt::Display) -> KeychainError {
        KeychainError::Backend {
            provider: FAKE_DISPLAY_NAME.to_string(),
            // The path, never the content: the content is passphrases.
            message: format!("{}: {message}", self.path.display()),
        }
    }

    fn read(&self) -> KeychainResult<Entries> {
        match std::fs::read(&self.path) {
            Ok(bytes) => serde_json::from_slice(&bytes).map_err(|err| self.failed(err)),
            Err(err) if err.kind() == std::io::ErrorKind::NotFound => Ok(Entries::new()),
            Err(err) => Err(self.failed(err)),
        }
    }

    /// `tmp` + `rename`, so a reader never sees half a file, and `0600` from the first byte.
    fn write(&self, entries: &Entries) -> KeychainResult<()> {
        let json = serde_json::to_vec_pretty(entries).map_err(|err| self.failed(err))?;
        let tmp = self.path.with_extension(format!("tmp.{}", std::process::id()));
        let mut file = std::fs::File::options()
            .write(true)
            .create_new(true)
            .mode(FILE_MODE)
            .open(&tmp)
            .map_err(|err| self.failed(err))?;
        let written = file
            .write_all(&json)
            .and_then(|()| file.sync_all())
            .map_err(|err| self.failed(err));
        drop(file);
        if let Err(err) = written {
            let _ = std::fs::remove_file(&tmp);
            return Err(err);
        }
        std::fs::rename(&tmp, &self.path).map_err(|err| {
            let _ = std::fs::remove_file(&tmp);
            self.failed(err)
        })
    }
}

impl Keychain for FakeKeychain {
    fn java_class_name(&self) -> &'static str {
        FAKE_CLASS
    }

    fn display_name(&self) -> &'static str {
        FAKE_DISPLAY_NAME
    }

    fn priority(&self) -> u32 {
        FAKE_PRIORITY
    }

    fn is_supported(&self) -> bool {
        !Self::flag(FAKE_UNSUPPORTED_ENV)
    }

    fn is_locked(&self) -> bool {
        Self::flag(FAKE_LOCKED_ENV)
    }

    fn store(&self, key: &str, display_name: Option<&str>, passphrase: &str) -> KeychainResult<()> {
        self.guard()?;
        let mut entries = self.read()?;
        entries.insert(
            key.to_string(),
            Entry {
                password: passphrase.to_string(),
                display_name: display_name.map(str::to_string),
            },
        );
        self.write(&entries)
    }

    fn load(&self, key: &str) -> KeychainResult<Option<Zeroizing<String>>> {
        self.guard()?;
        Ok(self
            .read()?
            .get(key)
            .map(|entry| Zeroizing::new(entry.password.clone())))
    }

    fn delete(&self, key: &str) -> KeychainResult<bool> {
        self.guard()?;
        let mut entries = self.read()?;
        if entries.remove(key).is_none() {
            return Ok(false);
        }
        self.write(&entries)?;
        Ok(true)
    }

    fn change(
        &self,
        key: &str,
        display_name: Option<&str>,
        passphrase: &str,
    ) -> KeychainResult<bool> {
        self.guard()?;
        // Javas `changePassphrase`: "Noop, if there is no item for the given key".
        if !self.read()?.contains_key(key) {
            return Ok(false);
        }
        self.store(key, display_name, passphrase)?;
        Ok(true)
    }
}
```

```rust
/// Ruling 6: `TouchIdKeychainAccess` and `MacSystemKeychainAccess` address the *same* generic
/// password items (same service, same account); only `requireOsAuthentication` differs, and the

    if class_name == MAC_TOUCH_ID_CLASS {
        MAC_SYSTEM_CLASS
    } else {
        class_name
    }

/// Every provider this build knows, highest [`Keychain::priority`] first.
///
/// While `$CRYPTO_KEYCHAIN_FAKE` is set this is exactly one entry -- the fake -- so no test can
/// reach the user's real keychain (ruling 8).
pub fn all_providers() -> Vec<Box<dyn Keychain>> {
    if let Some(fake) = fake::FakeKeychain::from_env() {
        return vec![Box::new(fake)];
    }
    let mut providers: Vec<Box<dyn Keychain>> = Vec::new();
    #[cfg(target_os = "macos")]
    providers.push(Box::new(macos::MacKeychain::new()));
    #[cfg(target_os = "linux")]
    {
        providers.push(Box::new(linux::SecretServiceKeychain::gnome_keyring()));
        providers.push(Box::new(linux::SecretServiceKeychain::secret_service()));
        providers.push(Box::new(kde::KdeWalletKeychain::new()));
    }
    providers.sort_by(|a, b| b.priority().cmp(&a.priority()));
    providers
}

/// `KeychainModule.provideKeychainAccessProvider`: nothing when `useKeychain` is off, otherwise
/// the supported provider whose Java class name matches, otherwise the first supported one.
pub fn for_settings(settings: &crate::settings::SettingsJson) -> Option<Box<dyn Keychain>> {
    if !settings.use_keychain {
        return None;
    }
    let wanted = canonical_provider_class(&settings.keychain_provider);
    let mut supported = all_providers()
        .into_iter()
        .filter(|provider| provider.is_supported())
        .peekable();
    let mut fallback: Option<Box<dyn Keychain>> = None;
    for provider in supported.by_ref() {
        if provider.java_class_name() == wanted {
            return Some(provider);
        }
        if fallback.is_none() {
            fallback = Some(provider);
        }
    }
    fallback
}
```

```rust
//! The macOS login keychain, byte-compatible with `org.cryptomator.macos.keychain.MacKeychain`.
//!
//! Java goes through JNI to `SecKeychainAddGenericPassword` / `SecKeychainFindGenericPassword`;
//! we go through `security-framework`'s `SecItemAdd` / `SecItemCopyMatching` / `SecItemDelete`.
//! Both address the same items: class `kSecClassGenericPassword`, `kSecAttrService` = the service
//! name, `kSecAttrAccount` = the vault id, the passphrase as UTF-8 in `kSecValueData`, and no
//! `kSecUseDataProtectionKeychain`, which is what keeps this on the file-based login keychain
//! rather than the data-protection one.
//!
//! `kSecAttrLabel` is set explicitly to the service name. `SecKeychainAddGenericPassword` does
//! that implicitly, `SecItemAdd` does not, and without it Keychain Access shows a nameless row
//! where the desktop app's entries say "Cryptomator".
//!
//! Reading an item that Cryptomator.app wrote makes macOS ask the user (the ACL lists the app,
//! not us). Spike B could not get past that dialog in a non-interactive session, which is why
//! every call from the CLI is wrapped in `keychain::with_timeout`.
use super::{
    service_name, Keychain, KeychainError, KeychainResult, DEFAULT_SERVICE, MAC_SYSTEM_CLASS,
};
use security_framework::passwords::{
    delete_generic_password, get_generic_password, set_generic_password_options, PasswordOptions,
};
use zeroize::Zeroizing;

/// `@Priority(1000)` on `MacSystemKeychainAccess`.
pub const MAC_PRIORITY: u32 = 1000;
/// `MacKeychain.OSSTATUS_NOT_FOUND`.
pub const ERR_SEC_ITEM_NOT_FOUND: i32 = -25300;
/// `NamedServiceProvider.getName()`; the desktop app localises it, we do not.
const MAC_DISPLAY_NAME: &str = "macOS Keychain";

#[derive(Debug, Clone)]
pub struct MacKeychain {
    service: String,
}

/// Whether an `OSStatus` means "no such item" rather than "it went wrong".
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Missing {
    Yes,
    No,
}

pub fn classify(code: i32) -> Missing {
    if code == ERR_SEC_ITEM_NOT_FOUND {
        Missing::Yes
    } else {
        Missing::No
    }
}

/// The error the CLI shows for an `OSStatus` that is not `errSecItemNotFound`. The code is part
/// of the message on purpose: it is what a bug report can be looked up by.
pub fn backend_error(code: i32, message: &str) -> KeychainError {
    KeychainError::Backend {
        provider: MAC_DISPLAY_NAME.to_string(),
        message: format!("{message} (OSStatus {code})"),
    }
}

impl Default for MacKeychain {
    fn default() -> Self {
        Self::new()
    }
}

impl MacKeychain {
    /// The service from `$CRYPTO_KEYCHAIN_SERVICE`, else `"Cryptomator"`.
    pub fn new() -> Self {
        Self {
            service: service_name(),
        }
    }

    pub fn with_service(service: String) -> Self {
        Self { service }
    }

    pub fn service(&self) -> &str {
        &self.service
    }

    fn options(&self, account: &str) -> PasswordOptions {
        let mut options = PasswordOptions::new_generic_password(&self.service, account);
        // `SecKeychainAddGenericPassword` sets the label to the service name; `SecItemAdd` does
        // not. Without this the item shows up nameless next to the desktop app's "Cryptomator".
        options.set_label(&self.service);
        options
    }

    fn map(&self, err: &security_framework::base::Error) -> KeychainError {
        backend_error(err.code(), &err.to_string())
    }
}

impl Keychain for MacKeychain {
    fn java_class_name(&self) -> &'static str {
        MAC_SYSTEM_CLASS
    }

    fn display_name(&self) -> &'static str {
        MAC_DISPLAY_NAME
    }

    fn priority(&self) -> u32 {
        MAC_PRIORITY
    }

    /// `MacSystemKeychainAccess.isSupported()` is a plain `true`: the login keychain is part of
    /// the operating system.
    fn is_supported(&self) -> bool {
        true
    }

    /// `MacSystemKeychainAccess.isLocked()` is a plain `false`: macOS unlocks the login keychain
    /// with the login and prompts by itself if it ever is locked.
    fn is_locked(&self) -> bool {
        false
    }

    fn store(&self, key: &str, _display_name: Option<&str>, passphrase: &str) -> KeychainResult<()> {
        // `display_name` has nowhere to go: the desktop app passes it too and `MacKeychain`
        // drops it -- a generic password item has service, account and label, and the label is
        // the service name (see `options`).
        set_generic_password_options(passphrase.as_bytes(), self.options(key))
            .map_err(|err| self.map(&err))
    }

    fn load(&self, key: &str) -> KeychainResult<Option<Zeroizing<String>>> {
        match get_generic_password(&self.service, key) {
            Ok(bytes) => {
                let bytes = Zeroizing::new(bytes);
                let text = std::str::from_utf8(&bytes).map_err(|_| KeychainError::Backend {
                    provider: MAC_DISPLAY_NAME.to_string(),
                    message: "the stored passphrase is not valid UTF-8".to_string(),
                })?;
                Ok(Some(Zeroizing::new(text.to_string())))
            }
            Err(err) if classify(err.code()) == Missing::Yes => Ok(None),
            Err(err) => Err(self.map(&err)),
        }
    }

    fn delete(&self, key: &str) -> KeychainResult<bool> {
        match delete_generic_password(&self.service, key) {
            Ok(()) => Ok(true),
            Err(err) if classify(err.code()) == Missing::Yes => Ok(false),
            Err(err) => Err(self.map(&err)),
        }
    }

    fn change(
        &self,
        key: &str,
        display_name: Option<&str>,
        passphrase: &str,
    ) -> KeychainResult<bool> {
        // `MacSystemKeychainAccess.changePassphrase`: delete, and store only if the delete found
        // something.
        if !self.delete(key)? {
            return Ok(false);
        }
        self.store(key, display_name, passphrase)?;
        Ok(true)
    }
}
```

```rust
fn enabled() -> bool {

        return true;
    }
    eprintln!("skipped: set CRYPTO_E2E_KEYCHAIN=1 to touch the real keychain");

/// A key nothing else uses, so a failed run leaves no doubt about what it belongs to.
fn scratch_key() -> String {
    let mut bytes = [0u8; 6];
    getrandom::fill(&mut bytes).expect("random");
    format!(
        "crypto-e2e-{}",
        bytes.iter().map(|b| format!("{b:02x}")).collect::<String>()
    )
}

/// Runs `op` under a timeout and turns "a dialog is waiting" into a skip.
fn attempt<T: Send + 'static>(
    what: &str,
    op: impl FnOnce() -> Result<T, KeychainError> + Send + 'static,
) -> Option<T> {
    match with_timeout_for("e2e", TEST_TIMEOUT, op) {
        Ok(value) => Some(value),
        Err(KeychainError::TimedOut { .. }) => {
            eprintln!("skipped: {what} did not answer in {TEST_TIMEOUT:?}; a system dialog is probably waiting");
            None
        }
        Err(KeychainError::Unsupported { hint, .. }) => {
            eprintln!("skipped: {what} is not supported here ({hint})");
            None
        }
        Err(KeychainError::Locked { .. }) => {
            eprintln!("skipped: {what} needs an unlocked keyring");

        }
        Err(err) => panic!("{what} failed: {err}"),

    })
    .expect("change answered");

    let (p, k) = (provider.clone(), key.clone());

    );
    let (p, k) = (provider.clone(), key.clone());
    assert!(

            .is_none(),

    let (p, k) = (provider.clone(), key.clone());
    assert!(!attempt("delete again", move || p.delete(&k)).expect("delete answered"));
    eprintln!("round trip: ok");

            "-A",

    }

}

/// Deletes the seeded entry however the test ends.
#[cfg(target_os = "macos")]
fn scopeguard(key: String) -> impl Drop {
    struct Guard(String);
    impl Drop for Guard {
        fn drop(&mut self) {
            let _ = std::process::Command::new("/usr/bin/security")
                .args(["delete-generic-password", "-s", "Cryptomator", "-a", &self.0])
                .status();
        }
    }
    Guard(key)
}
```

```rust
//! Passphrases in the FreeDesktop Secret Service (gnome-keyring, KeePassXC, KWallet's SS bridge).
//!
//! Shape of an item, matching what the desktop app's `integrations-linux` writes:
//!
//! | part       | value                                             |
//! |------------|---------------------------------------------------|
//! | collection | the default one, `login` when there is no default  |
//! | label      | `"Cryptomator"` (`$CRYPTO_KEYCHAIN_SERVICE`)       |
//! | attributes | `{"Vault": <vault id>, "Name": <display name>}`    |
//! | lookup     | `{"Vault": <vault id>}` -- never `Name`            |
//! | secret     | the passphrase, UTF-8, content type `text/plain`   |
//!
//! `GnomeKeyringKeychainAccess` is the same backend without the `Name` attribute, which is why
//! the lookup deliberately ignores `Name`: a renamed vault must still find its passphrase, and an
//! item written by either variant must be found by both.
//!
//! **Provenance:** `~/.m2/repository/org/cryptomator/integrations-linux/` does not exist on the
//! development machine, so this table comes from the design spec rather than from read Java
//! source. `crates/cryptomator-app/tests/keychain_e2e.rs` checks it against a live gnome-keyring.
//!
//! Blocking on purpose: `secret_service::blocking` drives zbus's blocking API, and with the
//! `tokio` feature `zbus::block_on` builds its own runtime in a `OnceLock`. That works outside a
//! tokio runtime -- which is where this always runs, namely on the worker thread of
//! [`crate::keychain::with_timeout`] -- and must never be called from inside one.
use super::{
    service_name, Keychain, KeychainError, KeychainResult, DEFAULT_SERVICE, GNOME_KEYRING_CLASS,
    SECRET_SERVICE_CLASS,
};
use secret_service::blocking::{Collection, SecretService};
use secret_service::{EncryptionType, Error as SsError};
use std::collections::HashMap;
use zeroize::Zeroizing;

/// Our own order, not a Java annotation: `integrations-linux` sources are not available here.
/// GNOME Keyring goes first because `Settings.DEFAULT_KEYCHAIN_PROVIDER` picks it on Linux.
pub const GNOME_KEYRING_PRIORITY: u32 = 1010;
pub const SECRET_SERVICE_PRIORITY: u32 = 1000;

/// The attribute every item is found by.
pub const VAULT_ATTRIBUTE: &str = "Vault";
/// The extra attribute `SecretServiceKeychainAccess` writes and `GnomeKeyringKeychainAccess` does not.
pub const NAME_ATTRIBUTE: &str = "Name";
/// The secret's content type.
pub const CONTENT_TYPE: &str = "text/plain";
/// The collection to fall back to when the service names no default one.
pub const LOGIN_COLLECTION_ALIAS: &str = "login";

const SECRET_SERVICE_DISPLAY_NAME: &str = "FreeDesktop Secret Service";
const GNOME_KEYRING_DISPLAY_NAME: &str = "GNOME Keyring (secret service)";

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Variant {
    /// `SecretServiceKeychainAccess`: writes `Vault` **and** `Name`.
    SecretService,
    /// `GnomeKeyringKeychainAccess`: writes only `Vault`.
    GnomeKeyring,
}

#[derive(Debug, Clone)]
pub struct SecretServiceKeychain {
    variant: Variant,
    service: String,
}

impl SecretServiceKeychain {
    pub fn secret_service() -> Self {
        Self::with_service(Variant::SecretService, service_name())
    }

    pub fn gnome_keyring() -> Self {
        Self::with_service(Variant::GnomeKeyring, service_name())
    }

    pub fn with_service(variant: Variant, service: String) -> Self {
        Self { variant, service }
    }

    /// The item label, which is the service name -- `"Cryptomator"` unless overridden.
    pub fn label(&self) -> &str {
        &self.service
    }

    /// What `create_item` writes.
    pub fn attributes<'a>(
        &self,
        key: &'a str,
        display_name: Option<&'a str>,
    ) -> Vec<(&'static str, &'a str)> {
        let mut attributes = vec![(VAULT_ATTRIBUTE, key)];
        if self.variant == Variant::SecretService {
            if let Some(name) = display_name {
                attributes.push((NAME_ATTRIBUTE, name));
            }
        }
        attributes
    }

    /// What `search_items` looks for: the vault id alone, so a rename never hides an item.
    pub fn search_attributes<'a>(&self, key: &'a str) -> Vec<(&'static str, &'a str)> {
        vec![(VAULT_ATTRIBUTE, key)]
    }

    pub fn map(&self, err: SsError) -> KeychainError {
        let provider = self.display_name().to_string();
        match err {
            SsError::Unavailable => KeychainError::Unsupported {
                provider,
                hint: "no secret service is running on the session bus; start gnome-keyring \
                       (or another Secret Service provider), or set useKeychain to false"
                    .to_string(),
            },
            SsError::Locked => KeychainError::Locked { provider },
            other => KeychainError::Backend {
                provider,
                message: other.to_string(),
            },
        }
    }

    fn connect(&self) -> KeychainResult<SecretService<'static>> {
        // `Dh`: the secret travels encrypted over the bus, like every other Secret Service client.
        SecretService::connect(EncryptionType::Dh).map_err(|err| self.map(err))
    }

    /// The default collection, or the one aliased `login`. `get_default_collection` already
    /// resolves the `default` alias; the fallback covers the keyrings that only have `login`.
    fn collection<'a>(&self, service: &'a SecretService<'a>) -> KeychainResult<Collection<'a>> {
        match service.get_default_collection() {
            Ok(collection) => Ok(collection),
            Err(SsError::NoResult) => service
                .get_collection_by_alias(LOGIN_COLLECTION_ALIAS)
                .map_err(|err| self.map(err)),
            Err(err) => Err(self.map(err)),
        }
    }

    /// Unlocks the collection if it is locked, so a first call after login does not fail with
    /// `Locked` when the keyring would happily prompt.
    fn unlocked<'a>(&self, service: &'a SecretService<'a>) -> KeychainResult<Collection<'a>> {
        let collection = self.collection(service)?;
        collection.ensure_unlocked().map_err(|err| self.map(err))?;
        Ok(collection)
    }
}

impl Keychain for SecretServiceKeychain {
    fn java_class_name(&self) -> &'static str {
        match self.variant {
            Variant::SecretService => SECRET_SERVICE_CLASS,
            Variant::GnomeKeyring => GNOME_KEYRING_CLASS,
        }
    }

    fn display_name(&self) -> &'static str {
        match self.variant {
            Variant::SecretService => SECRET_SERVICE_DISPLAY_NAME,
            Variant::GnomeKeyring => GNOME_KEYRING_DISPLAY_NAME,
        }
    }

    fn priority(&self) -> u32 {
        match self.variant {
            Variant::SecretService => SECRET_SERVICE_PRIORITY,
            Variant::GnomeKeyring => GNOME_KEYRING_PRIORITY,
        }
    }

    /// "must not throw any exceptions and should fail fast": a connection attempt and nothing else.
    fn is_supported(&self) -> bool {
        self.connect().is_ok()
    }

    fn is_locked(&self) -> bool {
        let Ok(service) = self.connect() else {
            return false;
        };
        self.collection(&service)
            .ok()
            .and_then(|collection| collection.is_locked().ok())
            .unwrap_or(false)
    }

    fn store(&self, key: &str, display_name: Option<&str>, passphrase: &str) -> KeychainResult<()> {
        let service = self.connect()?;
        let collection = self.unlocked(&service)?;
        let attributes: HashMap<&str, &str> =
            self.attributes(key, display_name).into_iter().collect();
        collection
            .create_item(
                self.label(),
                attributes,
                passphrase.as_bytes(),
                // `replace = true`: one item per vault, like the desktop app.
                true,
                CONTENT_TYPE,
            )
            .map(|_| ())
            .map_err(|err| self.map(err))
    }

    fn load(&self, key: &str) -> KeychainResult<Option<Zeroizing<String>>> {
        let service = self.connect()?;
        let collection = self.unlocked(&service)?;
        let attributes: HashMap<&str, &str> = self.search_attributes(key).into_iter().collect();
        let items = collection
            .search_items(attributes)
            .map_err(|err| self.map(err))?;
        let Some(item) = items.first() else {
            return Ok(None);
        };
        item.ensure_unlocked().map_err(|err| self.map(err))?;
        let secret = Zeroizing::new(item.get_secret().map_err(|err| self.map(err))?);
        let text = std::str::from_utf8(&secret).map_err(|_| KeychainError::Backend {
            provider: self.display_name().to_string(),
            message: "the stored passphrase is not valid UTF-8".to_string(),
        })?;
        Ok(Some(Zeroizing::new(text.to_string())))
    }

    fn delete(&self, key: &str) -> KeychainResult<bool> {
        let service = self.connect()?;
        let collection = self.unlocked(&service)?;
        let attributes: HashMap<&str, &str> = self.search_attributes(key).into_iter().collect();
        let items = collection
            .search_items(attributes)
            .map_err(|err| self.map(err))?;
        if items.is_empty() {
            return Ok(false);
        }
        // Several items for one vault should not happen (`replace = true`), but a keyring that
        // has them from an older version must end up empty, not half empty.
        for item in &items {
            item.delete().map_err(|err| self.map(err))?;
        }
        Ok(true)
    }

    fn change(
        &self,
        key: &str,
        display_name: Option<&str>,
        passphrase: &str,
    ) -> KeychainResult<bool> {
        // Javas `changePassphrase`: a noop when there is no item.
        if self.load(key)?.is_none() {
            return Ok(false);
        }
        self.store(key, display_name, passphrase)?;
        Ok(true)
    }
}
```

```rust
/// The keychain half of the password resolution: which provider, for which vault, under which
/// name in the error message.
#[derive(Debug)]
pub struct KeychainSource<'a> {
    pub keychain: &'a dyn crate::keychain::Keychain,
    /// The vault id -- the key the desktop app stores under.
    pub key: &'a str,
    /// The vault's display name (or id), for the "nothing stored for …" message.
    pub vault_label: &'a str,
}

impl KeychainSource<'_> {
    /// One `load`, under the timeout. `Ok(None)` is "nothing stored".
    fn load(&self) -> std::result::Result<Option<Zeroizing<String>>, crate::keychain::KeychainError> {
        // The closure has to be `'static` for the worker thread, so the two borrowed strings are
        // copied in. Neither is a secret.
        let keychain = self.keychain;
        let key = self.key.to_string();
        // SAFETY-free equivalent of a scoped thread: `with_timeout` needs `'static`, and a
        // trait object borrowed from the caller is not. The provider is cheap to describe but
        // not to clone, so the load runs directly and the *caller* is the one under a timeout --
        // see `read_keychain`, which wraps this whole call.
        let _ = &key;
        keychain.load(self.key)
    }
}

/// Runs one keychain load under [`crate::keychain::KEYCHAIN_TIMEOUT`].
///
/// The provider is behind a `&dyn`, which `with_timeout` cannot move to a worker thread, so the
/// timeout is applied one level up, in the commands, around the *owned* `Arc<dyn Keychain>` --
/// see `crypto::commands::keychain_call`, which every command goes through. Here the call is
/// direct.
fn read_keychain(source: &KeychainSource<'_>) -> std::result::Result<Option<Zeroizing<String>>, crate::keychain::KeychainError> {
    source.load()
}

/// [`read_passphrase`] with the two keychain steps of the source order.
///
/// The full order, first present source wins:
/// 1. `--password-stdin`
/// 2. `--password-file`
/// 3. `--password-env VAR`
/// 4. `$CRYPTO_PASSWORD`
/// 5. `--password-keychain` -- the keychain and nothing else; a missing entry is
///    [`AppError::KeychainNoEntry`] (exit code 8), never a prompt
/// 6. the keychain implicitly, when `source` is `Some` (i.e. `useKeychain` is on, a provider is
///    supported and `--no-keychain` was not given) **and** an entry exists; a missing entry, and
///    a keychain that fails, both fall through silently
/// 7. the interactive prompt
///
/// `$CRYPTO_PASSWORD` deliberately outranks the keychain: it is the source a script sets on
/// purpose, and it can never open a dialog.
///
/// # Errors
/// [`AppError::KeychainNoEntry`] / [`AppError::Keychain`] (exit code 8) for the explicit
/// `--password-keychain`, [`AppError::NoPasswordSource`] (2) when nothing is left.
pub fn read_passphrase_with_keychain(
    args: &PasswordArgs,
    prompt: &str,
    source: Option<KeychainSource<'_>>,
    io: &mut dyn PasswordIo,
) -> Result<Zeroizing<String>> {
    if args.password_keychain {
        let Some(source) = source else {
            return Err(AppError::Keychain(
                crate::keychain::KeychainError::Unsupported {
                    provider: "keychain".to_string(),
                    hint: "--password-keychain was given, but no keychain is in use here \
                           (--no-keychain, useKeychain=false, or no supported provider)"
                        .to_string(),
                },
            ));
        };
        return match read_keychain(&source)? {
            Some(passphrase) => Ok(normalize_passphrase(&passphrase)),
            None => Err(AppError::KeychainNoEntry {
                vault: source.vault_label.to_string(),
                provider: source.keychain.display_name().to_string(),
            }),
        };
    }
    // Everything that is not the keychain, minus the prompt: the prompt is step 7 and has to stay
    // *after* the implicit keychain step.
    if let Some(raw) = read_raw_without_prompt(args, DefaultEnv::Allowed, io)? {
        return Ok(normalize_passphrase(&raw));
    }
    if let Some(source) = source {
        match read_keychain(&source) {
            Ok(Some(passphrase)) => return Ok(normalize_passphrase(&passphrase)),
            // Nothing stored: the ordinary case for a vault whose password was never saved.
            Ok(None) => {}
            // A keyring that is missing, locked or slow must not cost the user the prompt.
            Err(err) => {
                log::debug!("keychain lookup for {} failed: {err}", source.key);
            }
        }
    }
    io.prompt(prompt)?
        .map(|typed| normalize_passphrase(&Zeroizing::new(typed)))
        .ok_or_else(|| no_source(args, DefaultEnv::Allowed))
}
```

```rust
fn read_raw_without_prompt(
    args: &PasswordArgs,
    default_env: DefaultEnv,
    io: &mut dyn PasswordIo,
) -> Result<Option<Zeroizing<String>>> {
    if args.password_stdin {
        return io
            .read_stdin_line()?
            .map(|line| Zeroizing::new(strip_line_ending(line)))
            .map(Some)
            .ok_or_else(|| no_source(args, default_env));
```

```rust
/// Runs one keychain call under [`cryptomator_app::keychain::KEYCHAIN_TIMEOUT`].
///
/// The provider is owned (`Arc<dyn Keychain>`), so it can be moved to the worker thread that
/// `with_timeout` gives up on. Every keychain access from a command goes through here -- that is
/// what keeps a stuck macOS ACL dialog from freezing the CLI (ruling 1).
pub fn keychain_call<T, F>(keychain: &Arc<dyn Keychain>, op: F) -> Result<T>
where
    T: Send + 'static,
    F: FnOnce(&dyn Keychain) -> cryptomator_app::keychain::KeychainResult<T> + Send + 'static,

    let name = keychain.display_name().to_string();

        op(keychain.as_ref())
    })
    .map_err(AppError::Keychain)?)
}
```

```rust
/// Resolves a vault reference for the keychain commands.
///
/// Unlike [`crate::commands::locked_vault`] this does **not** require the vault to be locked: a
/// keychain entry lives outside the vault directory, so storing or forgetting a passphrase is
/// safe while a daemon is serving it. What it does need is a path, because `password store`
/// verifies the passphrase against `masterkey.cryptomator` before saving it.
fn vault_for_keychain(ctx: &Ctx, reference: &str) -> Result<(VaultSettingsJson, PathBuf)> {
    let settings = ctx.store.load()?;
    let index = resolve_vault_index(&settings, reference)?;
    let vault = settings.directories[index].clone();
    let path = vault.path_buf().ok_or_else(|| AppError::InvalidValue {
        key: "path".to_string(),
        message: format!("vault {} has no path", vault.id),
    })?;
    Ok((vault, path))
}

/// `crypto password store <VAULT>`: read a passphrase, **verify it**, then save it.
///
/// The verification is the point (ruling 4). A wrong passphrase in the keychain is worse than no
/// passphrase at all: every later `crypto unlock` would take it, fail, and never ask the user --
/// so `open_vault` has to accept it first. The passphrase itself is read *without* the keychain
/// steps (`read_passphrase`, not `read_passphrase_with_keychain`): storing what is already
/// stored is not a thing.
///
/// # Errors
/// [`AppError::VaultNotFound`] (3), [`CoreError::InvalidPassphrase`] (4),
/// [`AppError::Keychain`] (8) when there is no keychain or it refuses.
pub fn store(ctx: &Ctx, args: StorePasswordArgs) -> Result<u8> {
    let keychain = ctx.keychain_required()?;
    let (vault, path) = vault_for_keychain(ctx, &args.vault)?;
    // Reject Hub and unsupported key ids before asking for any passphrase.
    read_vault_config(&path)?
        .key_id()?
        .require_masterkey_file()?;
    let passphrase = read_passphrase(&args.password, "Password: ", &mut SystemIo)?;
    // Exit 4 comes from here, before anything is written.
    let opened = open_vault(&path, &MasterkeyFileAccess::new(Vec::new()), &passphrase)?;
    drop(opened);

    let (key, display_name) = vault_key_and_name(&vault);
    let (key, display_name) = (key.to_string(), display_name.map(str::to_string));
    let secret = passphrase.to_string();
    keychain_call(&keychain, move |keychain| {
        keychain.store(&key, display_name.as_deref(), &secret)
    })?;
    drop(passphrase);

    let provider = keychain.display_name().to_string();
    ctx.out.emit(
        json!({ "vault": vault.id, "stored": true, "provider": provider }),
        || {
            format!(
                "Password stored for {} in {provider}.",
                vault.display_name.as_deref().unwrap_or(&vault.id)
            )
        },
    )?;
    Ok(exit::OK)
}

/// `crypto password forget <VAULT>`: remove the entry. Removing one that is not there is a
/// success, not an error -- the end state is what the user asked for.
///
/// # Errors
/// [`AppError::VaultNotFound`] (3), [`AppError::Keychain`] (8).
pub fn forget(ctx: &Ctx, reference: &str) -> Result<u8> {
    let keychain = ctx.keychain_required()?;
    let (vault, _path) = vault_for_keychain(ctx, reference)?;
    let key = vault.id.clone();
    let forgotten = keychain_call(&keychain, move |keychain| keychain.delete(&key))?;
    let provider = keychain.display_name().to_string();
    let label = vault
        .display_name
        .clone()
        .unwrap_or_else(|| vault.id.clone());
    ctx.out.emit(
        json!({ "vault": vault.id, "forgotten": forgotten, "provider": provider }),
        || {
            if forgotten {
                format!("Password for {label} removed from {provider}.")
            } else {
                format!("No password was stored for {label} in {provider}.")
            }
        },
    )?;
    Ok(exit::OK)
}
```

```rust
/// Saves `passphrase` for `vault`, replacing whatever was there.
///
/// Unlike [`crate::commands::password::update_keychain_entry`] this writes even when nothing was
/// stored yet -- it backs `--store-password`, where the user asked for exactly that. Returns
/// `false` when there is no keychain in this run (`--no-keychain`, `useKeychain = false`, no
/// supported provider), which is not a failure: the caller decides whether that deserves a
/// warning.
///
/// # Errors
/// [`AppError::Keychain`] (exit code 8) when a keychain is there but refuses.
pub fn store_passphrase_now(
    ctx: &Ctx,
    vault: &VaultSettingsJson,
    passphrase: &str,
) -> Result<bool> {
    let Some(keychain) = ctx.keychain()? else {
        return Ok(false);
    };
    let (key, display_name) = vault_key_and_name(vault);
    let (key, display_name) = (key.to_string(), display_name.map(str::to_string));
    let secret = passphrase.to_string();
    keychain_call(&keychain, move |keychain| {
        keychain.store(&key, display_name.as_deref(), &secret)
    })?;
    Ok(true)
}
```

```rust
/// `crypto vault remove <VAULT> [--forget-password]`.
///
/// The keychain entry goes first: after `settings.json` no longer lists the vault there is no id
/// left to look it up by. A keychain that refuses stops the removal, so the user can decide --
/// `crypto vault remove … ` without the flag always works.
pub fn remove(ctx: &Ctx, reference: &str, forget_password: bool) -> Result<u8> {
    let forgotten = if forget_password {
        let settings = ctx.store.load()?;
        let index = resolve_vault_index(&settings, reference)?;
        let vault = settings.directories[index].clone();
        let keychain = ctx.keychain_required()?;
        let key = vault.id.clone();
        keychain_call(&keychain, move |keychain| keychain.delete(&key))?
    } else {
        false
    };
    let removed = ctx.store.update(|settings| {
        let index = resolve_vault_index(settings, reference)?;
        Ok(settings.directories.remove(index))
    })?;
    ctx.out.emit(
        json!({
            "id": removed.id,
            "displayName": removed.display_name,
            "path": removed.path,
            "forgotten": forgotten,
        }),
        || {
            let name = removed.display_name.clone().unwrap_or_default();
            if forgotten {
                format!("Removed {name}; its password was removed from the keychain too.")
            } else {
                format!("Removed {name}")
            }
        },
    )?;
    Ok(exit::OK)
}
```

(Die genaue Gestalt des bisherigen `emit` in `remove` übernehmen – oben steht die Fassung mit dem zusätzlichen Feld; Feldnamen `id`/`displayName`/`path` bleiben, wie sie sind.)

```rust
//! `crypto keychain test`: what the keychain is, and whether it actually works.
//!
//! The round trip writes, reads, compares and deletes a throwaway entry under a random key. It
//! never touches a vault's entry, so it is safe to run at any time -- and it is the one command
//! that answers "why did my unlock not find the stored password?" without guessing.
use crate::commands::{keychain_call, Ctx};
use crate::exit;
use anyhow::Result;
use cryptomator_app::keychain::KeychainError;
use cryptomator_app::AppError;
use serde_json::json;

/// The self-test key's prefix. It is not a vault id, so it can never collide with a real entry.
pub const SELFTEST_PREFIX: &str = "crypto-selftest-";
/// What is stored and read back. Not a real passphrase, and it is deleted again immediately.
const SELFTEST_VALUE: &str = "crypto-selftest-value";

fn selftest_key() -> String {
    let mut bytes = [0u8; 6];
    // A failure here means the OS has no randomness, which is a hard failure everywhere else too.
    getrandom::fill(&mut bytes).unwrap_or_default();
    let hex: String = bytes.iter().map(|b| format!("{b:02x}")).collect();
    format!("{SELFTEST_PREFIX}{hex}")
}

/// `crypto keychain test`.
///
/// # Errors
/// [`AppError::Keychain`] (exit code 8) when there is no usable provider at all. A provider that
/// exists but fails the round trip is *reported* (with `roundTrip: "error: …"`) and then ends the
/// command with exit code 8 as well -- the output comes first, so the user sees the diagnosis.
pub fn test(ctx: &Ctx) -> Result<u8> {
    let keychain = ctx.keychain_required()?;
    let provider = keychain.java_class_name().to_string();
    let display_name = keychain.display_name().to_string();
    // `is_supported`/`is_locked` may talk to a keyring, so they get the timeout too.
    let supported = {
        let keychain = std::sync::Arc::clone(&keychain);
        keychain_call(&keychain, move |k| Ok(k.is_supported()))?
    };
    let locked = {
        let keychain = std::sync::Arc::clone(&keychain);
        keychain_call(&keychain, move |k| Ok(k.is_locked()))?
    };

    let round_trip = if supported {
        round_trip(ctx, &keychain)
    } else {
        Err(KeychainError::Unsupported {
            provider: display_name.clone(),
            hint: "isSupported() said no".to_string(),
        })
    };
    let round_trip_text = match &round_trip {
        Ok(()) => "ok".to_string(),
        Err(err) => format!("error: {err}"),
    };

    ctx.out.emit(
        json!({
            "provider": provider,
            "displayName": display_name,
            "supported": supported,
            "locked": locked,
            "roundTrip": round_trip_text,
        }),
        || {
            format!(
                "provider:     {provider}\n\
                 name:         {display_name}\n\
                 supported:    {supported}\n\
                 locked:       {locked}\n\
                 round trip:   {round_trip_text}"
            )
        },
    )?;

    match round_trip {
        Ok(()) => Ok(exit::OK),
        Err(err) => Err(AppError::Keychain(err).into()),
    }
}

/// Store, load, compare, delete -- and delete again even when a step in between failed.
fn round_trip(
    ctx: &Ctx,
    keychain: &std::sync::Arc<dyn cryptomator_app::keychain::Keychain>,
) -> std::result::Result<(), KeychainError> {
    let key = selftest_key();
    let result = round_trip_inner(ctx, keychain, &key);
    // Whatever happened, do not leave the throwaway entry behind.
    let cleanup_key = key.clone();
    let cleanup = keychain_call(keychain, move |k| k.delete(&cleanup_key));
    if let Err(err) = cleanup {
        // Only interesting when the round trip itself was fine; otherwise the first error is the
        // one that explains everything.
        if result.is_ok() {
            return Err(KeychainError::Backend {
                provider: keychain.display_name().to_string(),
                message: format!("the self-test entry {key} could not be removed: {err:#}"),
            });
        }
    }
    result
}

fn round_trip_inner(
    _ctx: &Ctx,
    keychain: &std::sync::Arc<dyn cryptomator_app::keychain::Keychain>,
    key: &str,
) -> std::result::Result<(), KeychainError> {
    let provider = keychain.display_name().to_string();
    let failed = |message: String| KeychainError::Backend {
        provider: provider.clone(),
        message,
    };
    let write_key = key.to_string();
    keychain_call(keychain, move |k| {
        k.store(&write_key, Some("crypto self-test"), SELFTEST_VALUE)
    })
    .map_err(|err| failed(format!("store failed: {err:#}")))?;

    let read_key = key.to_string();
    let loaded = keychain_call(keychain, move |k| k.load(&read_key))
        .map_err(|err| failed(format!("load failed: {err:#}")))?;
    match loaded.as_deref().map(String::as_str) {
        Some(SELFTEST_VALUE) => {}
        Some(_) => return Err(failed("load returned a different value than store wrote".into())),
        None => return Err(failed("store reported success but load found nothing".into())),
    }

    let delete_key = key.to_string();
    let deleted = keychain_call(keychain, move |k| k.delete(&delete_key))
        .map_err(|err| failed(format!("delete failed: {err:#}")))?;
    if !deleted {
        return Err(failed("delete found nothing to delete".into()));
    }
    let gone_key = key.to_string();
    let gone = keychain_call(keychain, move |k| k.load(&gone_key))
        .map_err(|err| failed(format!("load after delete failed: {err:#}")))?;
    if gone.is_some() {
        return Err(failed("the entry survived its own deletion".into()));
    }
    Ok(())
}
```

```markdown
## Keychain

`crypto` stores vault passwords in the same place the Cryptomator desktop app does, so a password
saved in one is found by the other.

| | macOS | Linux |
|---|---|---|
| backend | the login keychain (generic password) | FreeDesktop Secret Service (gnome-keyring, KeePassXC, KWallet's bridge) |
| provider | `org.cryptomator.macos.keychain.MacSystemKeychainAccess` | `org.cryptomator.linux.keychain.GnomeKeyringKeychainAccess` (default) or `…SecretServiceKeychainAccess` |
| where | service `Cryptomator`, account = the vault id | the login collection, label `Cryptomator`, attributes `Vault` (and `Name` for the Secret Service provider) |

Commands:

| Command | What it does |
|---|---|
| `crypto password store <VAULT>` | asks for the password, **verifies it against the vault** and only then saves it |
| `crypto password forget <VAULT>` | removes the saved password |
| `crypto unlock <VAULT> --store-password` | saves the password after the vault is mounted |
| `crypto vault create <PATH> --store-password` | saves the new password |
| `crypto vault remove <VAULT> --forget-password` | removes the saved password along with the vault |
| `crypto keychain test` | names the provider and does a store/load/delete round trip with a throwaway key |

`crypto password change` and `crypto recovery-key reset-password` update a saved password
automatically, exactly like the desktop app: if one is stored it follows the change, and if none is
stored nothing happens. A keychain that refuses is a warning, not a failed password change — the
new password is already on disk at that point, and `crypto password store <VAULT>` fixes the entry.

Settings: `crypto config set useKeychain false` turns all of this off; `crypto config set
keychainProvider <alias|class>` picks the backend, where the aliases are `macos`, `touchid`,
`secret-service`, `gnome-keyring` and `kde` and what is written to `settings.json` is always the
Java class name. `$CRYPTO_KEYCHAIN_SERVICE` overrides the service name / item label (the desktop
app's `cryptomator.integrationsMac.keychainServiceName`).

Things worth knowing:

- **Every keychain call gives up after 30 seconds** and reports exit `8` (`the keychain did not
  answer within 30 s; a system dialog may be waiting for you`). Without that, a dialog nobody is
  looking at would hang the command forever.
- **macOS asks the first time.** An entry written by Cryptomator.app belongs, as far as the keychain
  ACL is concerned, to Cryptomator.app; `crypto` is a different program, so macOS asks whether it
  may read it. Choose **“Always Allow”**. Until release binaries are signed with a stable
  Developer-ID identity, a re-signed build may be treated as a different program and ask again.
  Over SSH or in a headless session there is nobody to answer: use `--password-stdin`,
  `--password-file` or `$CRYPTO_PASSWORD` there.
- **Touch ID is read-only.** A `keychainProvider` of `TouchIdKeychainAccess` is served by the plain
  macOS backend — the items are the same ones — but passwords `crypto` writes have no Touch-ID
  access control on them.
- **KWallet is not supported.** `KDEWalletKeychainAccess` reports itself as unusable and points at
  `crypto config set keychainProvider secret-service`, which KWallet's own Secret Service bridge
  serves.
- **Linux needs a running Secret Service** on the session bus (`gnome-keyring-daemon
  --components=secrets`, KeePassXC with its Secret Service integration, …). Without one, the
  implicit keychain step is skipped and `crypto keychain test` says why.
- **`$CRYPTO_KEYCHAIN_FAKE=<file>`** replaces every real backend with a JSON file (mode `0600`), for
  tests and for debugging. While it is set, it is the *only* provider — nothing can reach the real
  keychain by accident. It stores passwords in the clear; do not point it at anything you keep.
```

- [ ] **Step 7: CI-Jobs** (`.github/workflows/ci.yml`, ans Dateiende)

```yaml
  # The keychain end-to-end tests. Like the mount jobs they are `#[ignore]`d twice over: `cargo
  # test` skips them, and even `--ignored` only touches a keyring when CRYPTO_E2E_KEYCHAIN=1 says
  # so. Everything else about the keychain -- every CLI flow -- runs against the file-backed fake
  # in the ordinary `test` job above.
  keychain-e2e-linux:
    runs-on: ubuntu-22.04
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - run: sudo apt-get update && sudo apt-get install -y gnome-keyring libsecret-1-0 dbus-x11
      - name: round-trip a passphrase through gnome-keyring
        # `dbus-run-session` gives the daemon a private session bus; `--unlock` with an empty
        # password on stdin creates and unlocks the default keyring, so nothing prompts.
        run: |
          set -euo pipefail
          dbus-run-session -- bash -c '
            eval "$(printf "" | gnome-keyring-daemon --unlock --components=secrets)"
            export GNOME_KEYRING_CONTROL
            CRYPTO_E2E_KEYCHAIN=1 cargo test -p cryptomator-app --test keychain_e2e --locked \
              -- --ignored --nocapture
          '

  # macOS runners have a login keychain, but an item another program wrote is behind an ACL that
  # can put a dialog in the way -- and there is nobody on a hosted runner to answer it. The test
  # seeds its own item with `-A` ("any application may read it"), which should avoid that, and
  # every call is under a 10-second timeout that turns a dialog into a "skipped" line rather than
  # a hang. `continue-on-error` keeps the job advisory until the runner image is known good; a
  # green job is only meaningful together with the "round trip: ok" line in its log.
  keychain-e2e-macos:
    runs-on: macos-15
    continue-on-error: true
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
      - run: CRYPTO_E2E_KEYCHAIN=1 cargo test -p cryptomator-app --test keychain_e2e --locked -- --ignored --nocapture
      # Nothing of ours may be left in the keychain afterwards.
      - name: the keychain is as it was
        if: always()
        run: |
          if security find-generic-password -s Cryptomator >/dev/null 2>&1; then
            echo "a Cryptomator keychain item survived the test run"
            security find-generic-password -s Cryptomator 2>&1 | head -20
            exit 1
          fi
          echo "no leftovers"
```

(Task 7), weil der Mount steht; ein fehlgeschlagenes Keychain-Update nach `password change` →
ebenfalls Warnung, Exit **0** (Task 6), weil die Passphrase auf der Platte schon neu ist.

## Ausführung

`superpowers:subagent-driven-development` mit Opus-5-Subagenten, ein frischer Subagent je Task,
Review zwischen den Tasks; Reihenfolge **1 → 10**. Abhängigkeiten: Task 2 braucht das Trait aus 1,
die Tasks 3 und 4 die Registry-Lücke aus 2, Task 5 die Provider aus 2–4, Task 6 den `Ctx` aus 5,
Task 7 die Helfer aus 5 und 6, Task 8 den `Ctx` aus 5. **Task 9 ist unabhängig** (M5-Nachträge,
`cryptomator-mount`) und darf parallel zu 1–8 laufen; Task 10 setzt auf allem auf.

Drei Tasks fassen die echte Keychain an und müssen ihre Ergebnisse im Report belegen:

- **Task 3, Step 8:** `CRYPTO_E2E_KEYCHAIN=1 … --test keychain_e2e -- --ignored`. Der Report
  enthält die `provider:`-Zeile, die `round trip: ok`-Zeile (oder die `skipped:`-Zeile samt
  Grund), ob ein Dialog erschienen ist, und den Nachweis, dass `security find-generic-password -s
  Cryptomator` danach Exit 44 meldet.
- **Task 8, Step 7:** `crypto keychain test` gegen die echte macOS-Keychain, mit der JSON-Zeile im
  Report.
- **Task 10, Step 9:** der manuelle Rauchtest über die CLI — `vault create --store-password`, die
  Attributzeilen aus `security find-generic-password` (ohne `-w`!), ein Unlock **ohne**
  `$CRYPTO_PASSWORD`, `password forget`, und die leere Keychain am Ende.

**Task 4 kann auf diesem Mac nicht ausgeführt werden.** Der Ausführende kompiliert dort mit
`cargo check --target x86_64-unknown-linux-gnu -p cryptomator-app --all-targets`, hält im Report
fest, dass der Linux-Lauf ausschließlich in den CI-Jobs `test` (ubuntu-22.04) und
`keychain-e2e-linux` stattfindet, und behauptet **nicht**, die Attributform sei verifiziert.

Alle übrigen Tasks laufen ohne echte Keychain: Sie setzen `CRYPTO_KEYCHAIN_FAKE` über
`Sandbox::crypto_keychain` / `Sandbox::crypto_daemon_keychain`, und solange die Variable gesetzt
ist, ist der Fake der einzige Provider — ein Test kann die Login-Keychain des Entwicklers nicht
erreichen. Die Tasks 5 und 7 setzen in ihren Daemon-Tests zusätzlich `CRYPTO_ENABLE_NULL_MOUNTER=1`
(über `Sandbox::crypto_daemon`).
