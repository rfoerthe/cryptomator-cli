# M8: Release 0.1.0 – Packaging, Manpages, Completions, CI Matrix and Hardening – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `crypto` becomes a program you can install. At the end there is `crypto completions <shell>`, a `crypto --version` that reports version, git SHA and target, an `xtask` toolbox (`man`, `completions`, `dist`, `lipo`, `deb`, `formula`), a `release.yml` that on a `v0.1.0` tag builds a universal binary, Linux tarballs, `.deb` packages, `SHA256SUMS` and a Homebrew formula, a complete CI matrix (macos-15, macos-13, ubuntu-22.04, ubuntu-22.04-arm) including `cargo deny` and an MSRV job, four hardenings from the deferred list, and the documentation a stranger needs to use all of it. The project is finished with this milestone.

**Architecture:** Four layers building on each other. (1) **The binary gets a library**: `crates/crypto` becomes lib + bin so another program in the workspace can build `crypto::cli::Cli::command()` — exactly what manpages and completions need outside of runtime. Plus a `build.rs` without a new dependency that puts `git rev-parse --short HEAD` and `$TARGET` into two `rustc-env` variables, and a `crypto completions <shell>` via `clap_complete`. (2) **`xtask/`** is its own workspace member, run through the alias `cargo xtask`, and does everything a release needs: `man` (clap_mangen → `target/man/`), `completions` (→ `target/completions/`), `dist <target>` (build, staging, `tar.gz`, `SHA256SUMS`), `lipo` (two macOS binaries → universal), `deb` (wrapper around `cargo-deb`) and `formula` (renders `packaging/homebrew/crypto.rb`). None of these steps upload anything — artifacts are produced only locally or in the workflow VM. (3) **Packaging and CI**: `[package.metadata.deb]` in `crates/crypto/Cargo.toml`, the Homebrew formula under `packaging/`, `.github/workflows/release.yml` on tag `v*`, and `ci.yml` grows two runners, a `supply-chain` job (`cargo deny`) and an MSRV job. (4) **Hardening**: an upper bound on the scrypt parameters of foreign masterkey files, `fsync` in the write path (`durability.rs`), and the anonymous *internet* password that Java creates before the AppleScript mount — the last open M6 item.

**Tech Stack:** Rust stable ≥ 1.89. **Two new crates, no more:** `clap_complete` 4.6 (already in the local registry cache as 4.6.9, matches `clap` 4.6.6 in the lockfile) and `clap_mangen` 0.2 (**not** available locally, `cargo add` needs the network; only `xtask` depends on it, not the shipped binary). Tools outside cargo: `git`, `tar`, `lipo` (Xcode, present), `ruby` (2.6.10, for the syntax check of the formula), `shasum`. **Not installed and to be installed via `cargo install` (network):** `cargo-deb`, `cargo-deny`. `cargo-audit` is deliberately **not** installed (Ruling 6). CI: GitHub Actions runners macos-15, macos-13, ubuntu-22.04, ubuntu-22.04-arm.

**Spec:** `docs/superpowers/specs/2026-09-04-crypto-cli-design.md` — section "Build & Packaging" (universal binary via `xtask lipo`, `MACOSX_DEPLOYMENT_TARGET=12.0`, optional Developer ID signature, Linux gnu x86_64/aarch64, CI matrix, `release.yml` with `cargo-deb` `Depends: fuse3` / `Recommends: gnome-keyring`, tar.gz + sha256, Homebrew formula with macFUSE/FUSE-T caveats), grammar lines `crypto completions <shell>` and `crypto --version`, directory tree (`xtask/`, `packaging/{homebrew/crypto.rb, deb/, man/}`, `.github/workflows/{ci.yml, release.yml}`), crate table (`clap_complete`, `cargo-deb`), milestone row **M8**, footnotes `[^m6-scope]` and `[^m7-scope]` (the internet password is moved to M8 there).

### Rulings for this milestone (comment in the code, document in Task 12)

1. **The first tagged version is `0.1.0`.** `workspace.package.version` is already at `0.1.0`; it is not touched. The CHANGELOG heading `## Unreleased` becomes `## 0.1.0 – 2026-09-08`, the subsections M0–M7 stay below it as chapters, M8 is added as another chapter. **No** empty `## Unreleased` section is created: the next milestone creates it, if there is one.
2. **`crypto --version` prints `crypto 0.1.0 (<sha>, <target>)`.** The SHA comes from a `build.rs` that calls `git rev-parse --short HEAD`; without a git repository or without `git` it says `unknown`, and the build does not abort. **No new dependency** — no `vergen`, no `git2`. `$CRYPTO_GIT_SHA` overrides the determined value so that a tarball build without `.git` (distribution, Homebrew) can still supply the information.
3. **Manpages come from `xtask`, not from the binary.** There is no `crypto manpage` and no hidden generator in the program: manpages are a build artifact that the release workflow produces and ships. They are **not** checked in — `packaging/man/` stays empty or is dropped, `target/man/` is the place. Rationale: a checked-in manpage is wrong from the first grammar commit on and nobody notices.
4. **Completions, by contrast, come from the binary** (`crypto completions <shell>`, grammar line of the spec) **and** from `xtask` (for the packages). Both routes call the same `clap_complete::generate` function on the same `Cli::command()`, so they cannot drift apart.
5. **Signature and notarization are out of scope.** `release.yml` signs nothing. `docs/release.md` documents the exact `codesign`/`notarytool` commands as a manual step, including the note that a bare Mach-O cannot be stapled. Rationale: without a Developer ID certificate and App Store Connect access, a signing step in CI is a step that can only be red.
6. **`cargo audit` is replaced by `cargo deny check advisories`, not run in addition.** Both read the same RustSec database; two jobs mean two failure sources and two configuration files for the same statement. The CI job is called `supply-chain` and runs `cargo deny check advisories bans licenses sources`.
7. **The internet password is written for the host the URI actually names.** Java hardcodes `-s localhost` even though its server listens on `127.0.0.1`; NetAuthAgent, however, looks up the host from the URI. We set `-s` to `server.local_addr().ip()`. Everything else is verbatim Java (`webdav-nio-adapter 3.0.2`, `MacAppleScriptMounter.mount`):
   ```
   security add-internet-password -a anonymous -s localhost -P <port> -r http \
     -D "Cryptomator WebDAV Access" \
     -T /System/Library/CoreServices/NetAuthAgent.app/Contents/MacOS/NetAuthSysAgent
   ```
   No `-w`: Java passes none, so the entry gets an empty password — and nothing secret ends up in argv. As in Java the call is **best effort**: if it fails or runs into its 10-second limit, a warning is logged and the mount proceeds anyway.
8. **Two deferred items stay deferred, with a rationale.** The `copy` path in `CryptoFs::copy` gets **no** dst truncation and no open-file guard: `crypto` has no `copy` command, the method is only called by the FUSE backend, and a guard without a caller that needs it is dead code with test cost. `encrypt_chunk` keeps its `assert!`s on oversize: they are invariants of the caller within the same crate (the chunk size comes from `cleartext_chunk_size()`), not a path for foreign data; a `Result` there would extend every caller by an unreachable error branch. Both are stated that way in the CHANGELOG under "Deliberately not implemented".
9. **The scrypt cap has three parts and is checked at load time, not only when computing.** `N ≤ 2^20`, `r ≤ 64`, and `128 · N · r ≤ 2 GiB`. Java/cryptolib knows **no** upper bound (`MasterkeyFileAccess.unlock` passes `scryptCostParam` through to `Scrypt.scrypt` unchecked) — that is the gap we close; the numbers are therefore ours, not Java's. The defaults (`N = 2^15`, `r = 8`, 32 MiB) are a factor of 64 below that, so real vaults are never affected. The error is `CoreError::InvalidMasterkeyFile` → exit **1**.
10. **`release.yml` does not write back into the repository.** The rendered Homebrew formula is attached as a release asset and written into the job summary; updating `packaging/homebrew/crypto.rb` by hand is a step in `docs/release.md`. A workflow with write access to `main` is an attack target a one-man project does not need.
11. **`cargo xtask dist` always builds with `--locked`.** A release artifact whose dependencies shifted during the build is not reproducible. The same goes for every `cargo` call in `release.yml`.

```rust
//! The release surface of the binary: `crypto completions <shell>` and `crypto --version`.
//! Nothing here needs a vault, a settings file or a keychain, so there is no `Sandbox`.
use assert_cmd::Command;
use predicates::prelude::*;

fn crypto() -> Command {
    Command::cargo_bin("crypto").expect("the `crypto` binary is built")
}

/// One script per shell, and each one has to look like that shell's completion script rather
/// than merely be non-empty: a generator wired to the wrong shell would still print something.
#[test]
fn every_supported_shell_gets_its_own_script() {
    let expected: &[(&str, &str)] = &[
        ("bash", "complete -F _crypto"),
        ("zsh", "#compdef crypto"),
        ("fish", "complete -c crypto"),
        ("elvish", "edit:completion:arg-completer[crypto]"),
        ("powershell", "Register-ArgumentCompleter"),
    ];
    for (shell, marker) in expected {
        crypto()
            .args(["completions", shell])
            .assert()
            .success()
            .stdout(predicate::str::contains(*marker));
    }
}

/// The generated script has to know the subcommands, otherwise it completes nothing useful.
#[test]
fn the_bash_script_mentions_the_subcommands() {
    let out = crypto().args(["completions", "bash"]).output().unwrap();
    let script = String::from_utf8(out.stdout).unwrap();
    for subcommand in ["vault", "unlock", "health", "migrate", "completions"] {
        assert!(script.contains(subcommand), "bash script is missing {subcommand}");
    }
    // `__daemon` is `hide = true`; a hidden command must not be advertised.
    assert!(!script.contains("__daemon"), "the hidden daemon command leaked into the script");
}

/// An unknown shell is a usage error, and clap lists the valid values.
#[test]
fn an_unknown_shell_is_exit_two_and_names_the_valid_ones() {
    crypto()
        .args(["completions", "tcsh"])
        .assert()
        .code(2)
        .stderr(predicate::str::contains("bash").and(predicate::str::contains("zsh")));
}

/// Completions must work when there is no readable settings file: a user who broke their
/// `settings.json` still has to be able to install completions, and the shell startup that runs
/// this command must never block on anything.
#[test]
fn completions_do_not_read_the_settings_file() {
    let dir = tempfile::tempdir().unwrap();
    let broken = dir.path().join("settings.json");
    std::fs::write(&broken, b"{ this is not json").unwrap();
    crypto()
        .args(["--settings"])
        .arg(&broken)
        .args(["completions", "zsh"])
        .assert()
        .success()
        .stdout(predicate::str::contains("#compdef crypto"));
}
```

```rust
//! Puts the commit and the target triple into the binary, for `crypto --version`.
//!
//! Deliberately dependency-free: it shells out to `git` and falls back to `unknown`. A build from
//! a source tarball has no `.git` and must still succeed -- and can still name its commit by
//! setting `$CRYPTO_GIT_SHA`, which wins over the git call.
use std::path::{Path, PathBuf};
use std::process::Command;

fn main() {
    println!("cargo:rerun-if-changed=build.rs");
    println!("cargo:rerun-if-env-changed=CRYPTO_GIT_SHA");

    let sha = std::env::var("CRYPTO_GIT_SHA")
        .ok()
        .map(|s| s.trim().to_string())
        .filter(|s| !s.is_empty())
        .or_else(git_sha)
        .unwrap_or_else(|| "unknown".to_string());
    // `TARGET` is set by cargo for every build script; the fallback only matters if that ever
    // stops being true.
    let target = std::env::var("TARGET").unwrap_or_else(|_| "unknown".to_string());

    println!("cargo:rustc-env=CRYPTO_BUILD_SHA={sha}");
    println!("cargo:rustc-env=CRYPTO_BUILD_TARGET={target}");

    // Rebuild when HEAD moves, so the sha in the binary is not the one from three commits ago.
    // In a worktree `.git` is a file pointing elsewhere; watching it is still the right trigger,
    // because switching branches rewrites it.
    if let Some(head) = git_head_path() {
        println!("cargo:rerun-if-changed={}", head.display());
    }
}

/// `git rev-parse --short HEAD` in the manifest directory. `None` when git is missing, the
/// directory is not a repository, or the call fails for any other reason -- never a panic: a
/// build script that dies takes the whole build with it.
fn git_sha() -> Option<String> {
    let dir = std::env::var("CARGO_MANIFEST_DIR").ok()?;
    let out = Command::new("git")
        .args(["rev-parse", "--short", "HEAD"])
        .current_dir(&dir)
        .output()
        .ok()?;
    if !out.status.success() {
        return None;
    }
    let sha = String::from_utf8(out.stdout).ok()?.trim().to_string();
    (!sha.is_empty()).then_some(sha)
}

/// The file whose change means "HEAD moved": `<toplevel>/.git/HEAD`, or the `.git` file itself in
/// a worktree. `None` outside a repository.
fn git_head_path() -> Option<PathBuf> {
    let dir = std::env::var("CARGO_MANIFEST_DIR").ok()?;
    let out = Command::new("git")
        .args(["rev-parse", "--show-toplevel"])
        .current_dir(&dir)
        .output()
        .ok()?;
    if !out.status.success() {
        return None;
    }
    let top = String::from_utf8(out.stdout).ok()?.trim().to_string();
    let dot_git = Path::new(&top).join(".git");
    if dot_git.is_dir() {
        Some(dot_git.join("HEAD"))
    } else if dot_git.is_file() {
        Some(dot_git)
    } else {
        None
    }
}
```

```rust
/// The page name for a command path: `[] -> crypto.1`, `["vault","create"] -> crypto-vault-create.1`.
pub fn man_file_name(path: &[&str]) -> String {
    let mut name = String::from("crypto");
    for segment in path {
        name.push('-');
        name.push_str(segment);
    }
    name.push_str(".1");
    name
}

/// Renders `cmd` and every visible subcommand, recursively, into `out_dir`. Returns what it wrote.
pub fn render_all(cmd: clap::Command, out_dir: &Path) -> Result<Vec<PathBuf>> {
    std::fs::create_dir_all(out_dir)
        .with_context(|| format!("cannot create {}", out_dir.display()))?;
    // `build()` resolves defaults, propagated settings and help templates once, up front; without
    // it the nested `get_subcommands()` walk sees a half-configured tree.
    let mut cmd = cmd;
    cmd.build();
    let mut written = Vec::new();
    render_recursive(&cmd, &mut Vec::new(), out_dir, &mut written)?;
    Ok(written)
}

fn render_recursive(
    cmd: &clap::Command,
    path: &mut Vec<String>,
    out_dir: &Path,
    written: &mut Vec<PathBuf>,
) -> Result<()> {
    let segments: Vec<&str> = path.iter().map(String::as_str).collect();
    let file_name = man_file_name(&segments);
    // `clap_mangen` takes the command's own name for the page title, and a subcommand's name is
    // the bare word (`create`). Renaming the clone gives `CRYPTO-VAULT-CREATE(1)` in the header
    // and `crypto-vault-create` in the synopsis -- git's convention, and what `man` will find.
    let titled = cmd.clone().name(file_name.trim_end_matches(".1").to_string());
    let mut buf: Vec<u8> = Vec::new();
    clap_mangen::Man::new(titled)
        .render(&mut buf)
        .with_context(|| format!("cannot render {file_name}"))?;
    let target = out_dir.join(&file_name);
    std::fs::write(&target, &buf).with_context(|| format!("cannot write {}", target.display()))?;
    written.push(target);

    for sub in cmd.get_subcommands() {
        // Hidden commands (`__daemon`) get no page: documenting them would invite running them.
        if sub.is_hide_set() {
            continue;
        }
        path.push(sub.get_name().to_string());
        render_recursive(sub, path, out_dir, written)?;
        path.pop();
    }
    Ok(())
}
```

```rust
/// Writes all five scripts into `out_dir`, returning the paths in the order of [`SHELLS`].
pub fn generate_all(out_dir: &Path) -> Result<Vec<PathBuf>> {

        written.push(target);
    }
    Ok(written)
```

```rust
pub fn staging_dir_name(version: &str, target: &str) -> String {
    format!("crypto-{version}-{target}")

pub fn archive_name(version: &str, target: &str) -> String {
    format!("{}.tar.gz", staging_dir_name(version, target))

/// One `sha256sum`-format line for `path`: lowercase hex, two spaces, the bare file name.
pub fn sha256_line(path: &Path) -> Result<String> {
    let bytes = std::fs::read(path).with_context(|| format!("cannot read {}", path.display()))?;
    let digest = Sha256::digest(&bytes);
    let hex = data_encoding::HEXLOWER.encode(&digest);
    let name = path
        .file_name()
        .and_then(|n| n.to_str())
        .with_context(|| format!("not a file name: {}", path.display()))?;
    Ok(format!("{hex}  {name}"))
}

/// Builds `target` (unless `no_build`), stages everything into `target/dist/<name>/`, packs it and
/// appends its checksum to `target/dist/SHA256SUMS`. Returns the archive path.
pub fn dist(root: &Path, target: &str, no_build: bool) -> Result<PathBuf> {
    if !no_build {
        build(root, target)?;
    }
    let dist_dir = root.join("target/dist");
    let stage = dist_dir.join(staging_dir_name(VERSION, target));
    // A stale staging directory from a previous run would smuggle old files into the archive.
    if stage.exists() {
        std::fs::remove_dir_all(&stage)
            .with_context(|| format!("cannot clear {}", stage.display()))?;
    }
    let layout = staging_layout();
    std::fs::create_dir_all(&stage)?;

    let binary = root.join("target").join(target).join("release").join(layout.binary);
    if !binary.is_file() {
        bail!(
            "{} does not exist; run without --no-build, or build it first",
            binary.display()
        );
    }
    copy_preserving_mode(&binary, &stage.join(layout.binary))?;
    for doc in layout.docs {
        copy_preserving_mode(&root.join(doc), &stage.join(doc))?;
    }
    crate::man::render_all(
        <crypto::cli::Cli as clap::CommandFactory>::command(),
        &stage.join(layout.man_subdir),
    )?;
    crate::completions::generate_all(&stage.join(layout.completions_subdir))?;

    let archive = dist_dir.join(archive_name(VERSION, target));
    // `-C dist` so the archive holds `crypto-0.1.0-<target>/…` and not `target/dist/…`.
    let status = Command::new("tar")
        .arg("-czf")
        .arg(&archive)
        .arg("-C")
        .arg(&dist_dir)
        .arg(staging_dir_name(VERSION, target))
        .status()
        .context("cannot run tar")?;
    if !status.success() {
        bail!("tar failed with {status}");
    }
    let line = sha256_line(&archive)?;
    let sums = dist_dir.join("SHA256SUMS");
    let mut existing = std::fs::read_to_string(&sums).unwrap_or_default();
    // Re-running dist for the same target replaces its line rather than adding a second one.
    let name = archive.file_name().unwrap().to_string_lossy().into_owned();
    existing = existing
        .lines()
        .filter(|l| !l.ends_with(&format!("  {name}")))
        .map(|l| format!("{l}\n"))
        .collect();
    existing.push_str(&line);
    existing.push('\n');
    std::fs::write(&sums, existing)?;
    println!("{}", archive.display());
    println!("{line}");
    Ok(archive)
}

/// `cargo build --release --locked -p crypto --target <target>` (Ruling 11), with the deployment
/// target the spec fixes for macOS.
fn build(root: &Path, target: &str) -> Result<()> {
    let mut command = Command::new(std::env::var("CARGO").unwrap_or_else(|_| "cargo".into()));
    command
        .current_dir(root)
        .args(["build", "--release", "--locked", "-p", "crypto", "--target", target]);
    if target.ends_with("-apple-darwin") {
        // Spec, "Build & Packaging": the binary must run on macOS 12 and later.
        command.env("MACOSX_DEPLOYMENT_TARGET", "12.0");
    }
    let status = command.status().context("cannot run cargo")?;
    if !status.success() {
        bail!("cargo build failed with {status}");
    }
    Ok(())
}

/// `std::fs::copy` keeps the permission bits, which is what the executable bit rides on.
fn copy_preserving_mode(from: &Path, to: &Path) -> Result<()> {
    if let Some(parent) = to.parent() {
        std::fs::create_dir_all(parent)?;
    }
    std::fs::copy(from, to)
        .with_context(|| format!("cannot copy {} to {}", from.display(), to.display()))?;
    Ok(())
}
```

```rust
/// Combines the two binaries and verifies the result really is fat, because `lipo -create` on two
/// copies of the same architecture succeeds and produces a thin file.
pub fn lipo(arm64: &Path, x86_64: &Path, out: &Path) -> Result<()> {
    if let Some(parent) = out.parent() {
        std::fs::create_dir_all(parent)?;
    }
    let status = lipo_command(arm64, x86_64, out).status().context("cannot run lipo")?;
    if !status.success() {
        bail!("lipo failed with {status}");
    }
    let info = Command::new("lipo").arg("-info").arg(out).output().context("cannot run lipo -info")?;
    let text = String::from_utf8_lossy(&info.stdout).into_owned();
    if !(text.contains("arm64") && text.contains("x86_64")) {
        bail!("the combined binary is not universal: {}", text.trim());
    }
    println!("{}", text.trim());
    Ok(())
}
```

```rust
/// Generates the assets the manifest points at, then builds the package.
pub fn deb(root: &Path, target: &str) -> Result<()> {
    crate::man::render_all(
        <crypto::cli::Cli as clap::CommandFactory>::command(),
        &root.join("target/man"),
    )?;
    crate::completions::generate_all(&root.join("target/completions"))?;
    let out_dir = root.join("target/dist");

        .current_dir(root)

/// The manpages `cargo xtask man` produced, for the asset check in the tests and for a caller that
/// wants to list them.
pub fn man_asset_paths(man_dir: &Path) -> Result<Vec<PathBuf>> {
    let mut pages: Vec<PathBuf> = std::fs::read_dir(man_dir)
        .with_context(|| format!("cannot list {}", man_dir.display()))?
        .flatten()
        .map(|entry| entry.path())
        .filter(|path| path.extension().is_some_and(|e| e == "1"))
```

```rust
/// The formula text for one release. A template with three holes rather than a file to edit:
/// url and sha256 change every time, and a stale sha256 fails at install time.
pub fn render_formula(version: &str, url: &str, sha256: &str) -> String {
    format!(
        r#"# Homebrew formula for crypto, the Cryptomator command line client.
#
# Generated by `cargo xtask formula`; do not edit by hand. See docs/release.md.
class Crypto < Formula
  desc "Cryptomator vaults from the command line"
  homepage "https://github.com/rfoerthe/cryptomator-cli"
  url "{url}"
  sha256 "{sha256}"
  version "{version}"
  license "AGPL-3.0-only"

  # The bottle is a Universal Mach-O built for macOS 12 and later. Linux gets .deb packages and a
  # tarball from the same release instead.
  depends_on :macos

  def install
    bin.install "crypto"
    man1.install Dir["man/*.1"]
    bash_completion.install "completions/crypto.bash" => "crypto"
    zsh_completion.install "completions/_crypto"
    fish_completion.install "completions/crypto.fish"
    doc.install "README.md", "CHANGELOG.md", "LICENSE"
  end

  def caveats
    <<~EOS
      crypto does not ship a file system driver. To mount a vault as a directory,
      install one of:

        brew install --cask macos-fuse-t/homebrew-cask/fuse-t   # no kernel extension
        brew install --cask macfuse                             # system extension, needs a reboot

      Without either, `crypto unlock --mounter webdav` serves the vault over a
      loopback WebDAV server and needs no driver at all.

      `crypto completions <shell>` prints a completion script if you would rather
      install one by hand than use the ones this formula placed.
    EOS
  end

  test do
    assert_match "crypto {version}", shell_output("#{{bin}}/crypto --version")
    assert_match "#compdef crypto", shell_output("#{{bin}}/crypto completions zsh")
  end
end
"#
    )
}
```

The doubled braces in `#{{bin}}` are intentional: Rust's `format!` eats single ones, and Ruby needs `#{bin}`.

```rust
//! The GitHub workflows are checked here rather than by a linter nobody has installed: they parse
//! as YAML, and the jobs the release depends on exist with the runners and targets they need.
use std::path::PathBuf;
use std::process::Command;

fn root() -> PathBuf {
    PathBuf::from(env!("CARGO_MANIFEST_DIR")).parent().unwrap().to_path_buf()
}

/// Runs a Ruby one-liner over a workflow and returns its stdout, failing the test with Ruby's own
/// message when the script raises -- a YAML syntax error included.
fn ruby_over(workflow: &str, script: &str) -> String {
    let path = root().join(".github/workflows").join(workflow);
    let out = Command::new("ruby")
        .arg("-ryaml")
        .arg("-e")
        .arg(script)
        .arg(path)
        .output()
        .expect("ruby is on the PATH");
    assert!(
        out.status.success(),
        "ruby failed on {workflow}: {}",
        String::from_utf8_lossy(&out.stderr)
    );
    String::from_utf8(out.stdout).expect("ruby printed utf-8")
}

#[test]
fn both_workflows_are_valid_yaml() {

        assert!(!out.trim().is_empty(), "{workflow} declares no jobs");

}
```

on:
  push:
    tags: ["v*"]
  # So a failed release can be re-run against an existing tag without pushing a new one.
  workflow_dispatch:
    inputs:
      tag:
        description: The tag to build (e.g. v0.1.0)
        required: true

# reads the checkout and passes artifacts along.
permissions:
  contents: read

jobs:
  # One tarball per target: binary, README, LICENSE, CHANGELOG, manpages, completions, and the
  # matching line for SHA256SUMS. `cargo xtask dist` does all of it with --locked.
  build:
    strategy:
      # A red macOS build must not cancel the Linux ones: knowing which targets are broken is the
      # point of a release build.
      fail-fast: false
      matrix:
        include:
          - os: macos-15
            target: aarch64-apple-darwin
          - os: macos-13
            target: x86_64-apple-darwin
          - os: ubuntu-22.04
            target: x86_64-unknown-linux-gnu
          - os: ubuntu-22.04-arm
            target: aarch64-unknown-linux-gnu
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
        with:
          # `git rev-parse --short HEAD` in build.rs needs real history, not a graft.
          fetch-depth: 0
      - uses: dtolnay/rust-toolchain@stable
        with:
          targets: ${{ matrix.target }}
      - uses: Swatinem/rust-cache@v2
        with:
          key: release-${{ matrix.target }}
      - run: cargo xtask dist --target ${{ matrix.target }}
      # The raw binary travels too: the `universal` job runs `lipo` over the two macOS ones, and
      # the `deb` jobs package the Linux ones without rebuilding.
      - uses: actions/upload-artifact@v4
        with:
          name: dist-${{ matrix.target }}
          path: |
            target/dist/crypto-*-${{ matrix.target }}.tar.gz
            target/dist/SHA256SUMS
            target/${{ matrix.target }}/release/crypto
          if-no-files-found: error
          retention-days: 7

  # The Universal Mach-O the Homebrew formula points at.
  universal:
    needs: build
    runs-on: macos-15
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: dtolnay/rust-toolchain@stable
      - uses: actions/download-artifact@v4

          name: dist-aarch64-apple-darwin
          path: arm64
      - uses: actions/download-artifact@v4
        with:
          name: dist-x86_64-apple-darwin
          path: x86_64

      # the same tarball layout `dist` produces.
      - run: |
          chmod +x arm64/target/aarch64-apple-darwin/release/crypto \
                   x86_64/target/x86_64-apple-darwin/release/crypto
          cargo xtask lipo \
            --arm64 arm64/target/aarch64-apple-darwin/release/crypto \
            --x86-64 x86_64/target/x86_64-apple-darwin/release/crypto
      # The formula the release ships. Its sha256 is the one of the tarball built one step above,
      # so the two can never disagree.
      - name: render the Homebrew formula

          set -euo pipefail
          VERSION=$(sed -n 's/^version = "\(.*\)"/\1/p' Cargo.toml | head -1)
          SHA=$(shasum -a 256 "target/dist/crypto-$VERSION-universal-apple-darwin.tar.gz" | cut -d' ' -f1)
          cargo xtask formula --sha256 "$SHA" > target/dist/crypto.rb
          {
            echo '## Homebrew formula'
            echo '```ruby'
            cat target/dist/crypto.rb
            echo '```'
          } >> "$GITHUB_STEP_SUMMARY"

        with:
          name: dist-universal-apple-darwin

            target/dist/crypto-*-universal-apple-darwin.tar.gz
            target/dist/SHA256SUMS
            target/dist/crypto.rb

          retention-days: 7

          - os: ubuntu-22.04-arm
            target: aarch64-unknown-linux-gnu

### Task 9: Hardening — an upper bound on the scrypt parameters of foreign masterkey files

**Why:** `masterkey.cryptomator` is a file an attacker can supply (a "shared vault", a cloud folder, an email attachment). `scryptCostParam` and `scryptBlockSize` go into `scrypt::Params::new` unchecked today; scrypt needs `128 · N · r` bytes. /// The largest `scryptCostParam` (`N`) a masterkey file may ask for.
```rust
///
/// cryptolib has no limit at all -- `MasterkeyFileAccess.unlock` hands the value straight to
/// `Scrypt.scrypt` -- and a `masterkey.cryptomator` is a file someone else can hand you. 2^20 is
/// 32 times the library's own default and, at the default block size, a one-gigabyte allocation:
/// far beyond anything a Cryptomator release has ever written, and still not a machine killer.
pub const MAX_SCRYPT_COST_PARAM: u32 = 1 << 20;
/// The largest `scryptBlockSize` (`r`). Every Cryptomator vault uses 8.
pub const MAX_SCRYPT_BLOCK_SIZE: u32 = 64;
/// The memory ceiling for one derivation. scrypt's working set is `128 * N * r` bytes, so the two
/// limits above are not enough on their own: N = 2^20 with r = 64 is 8 GiB with both inside their
/// individual bounds.
pub const MAX_SCRYPT_MEMORY_BYTES: u64 = 2 * 1024 * 1024 * 1024;

/// Checks `cost_param` and `block_size` against the limits above. Split out from [`scrypt_kek`]
/// so a file can be rejected when it is *read*, before a passphrase is asked for.
pub fn check_scrypt_params(cost_param: u32, block_size: u32) -> Result<()> {
    if cost_param < 2 || !cost_param.is_power_of_two() {
        return Err(CoreError::InvalidArgument(
            "scrypt N must be a power of 2 greater than 1".into(),
        ));
    }
    if cost_param > MAX_SCRYPT_COST_PARAM {
        return Err(CoreError::InvalidArgument(format!(
            "scrypt cost parameter {cost_param} exceeds the limit of {MAX_SCRYPT_COST_PARAM}"
        )));
    }
    if block_size == 0 || block_size > MAX_SCRYPT_BLOCK_SIZE {
        return Err(CoreError::InvalidArgument(format!(
            "scrypt block size {block_size} is outside 1..={MAX_SCRYPT_BLOCK_SIZE}"
        )));
    }
    let memory = 128u64 * u64::from(cost_param) * u64::from(block_size);
    if memory > MAX_SCRYPT_MEMORY_BYTES {
        return Err(CoreError::InvalidArgument(format!(
            "scrypt parameters N={cost_param}, r={block_size} would need {} MiB of memory, \
             more than the {} MiB limit",
            memory / (1024 * 1024),
            MAX_SCRYPT_MEMORY_BYTES / (1024 * 1024)
        )));
    }
    Ok(())
}
```

### Task 10: Hardening — `fsync` in the write path

**Why:** two places write data a power cut must not cost, and rely on `rename` without the target directory ever being synced. (1) `MasterkeyFileAccess::persist` writes `masterkey.cryptomator.tmp`, calls `sync_all()` on it — and then renames without syncing the directory: after a crash the contents can be on the platter and the directory entry not, and the vault has no key file at all any more. (2) `CryptoFs::write_from_reader` closes its handle with `flush()`, which writes but does not sync; `crypto fs put` renames immediately afterwards. **Honest note for the implementer:** whether an `fsync` really happened cannot be observed from a test — no file system reports it back. //! Making a rename survive a power cut.
```rust
//!
//! `write(tmp) + fsync(tmp) + rename(tmp, target)` is atomic with respect to *readers*: nobody
//! ever sees a half-written file. It is not durable: the rename lives in the directory, and the
//! directory has its own dirty pages. After a crash the file's contents can be on the platter
//! while the entry that names it is not -- and for `masterkey.cryptomator` that means a vault
//! with no key file at all.
//!
//! The fix is one more `fsync`, on the directory. Whether it actually happened cannot be observed
//! from a test -- no file system reports it -- so what the tests below pin is the behaviour
//! around it: the rename takes effect, the errors are the right ones, and a caller cannot
//! silently get the non-durable version.
use std::io;
use std::path::Path;

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn syncing_a_real_directory_succeeds() {
        let dir = tempfile::tempdir().unwrap();
        sync_dir(dir.path()).expect("a directory that exists can be synced");
    }

    /// A caller that passes a path that is not there has a bug, and must hear about it rather
    /// than get a silent `Ok`.
    #[test]
    fn syncing_a_missing_directory_is_not_found() {
        let dir = tempfile::tempdir().unwrap();
        let err = sync_dir(&dir.path().join("nope")).unwrap_err();
        assert_eq!(err.kind(), io::ErrorKind::NotFound);
    }

    /// A file is not a directory, and opening one to fsync it would sync the wrong thing.
    #[test]
    fn syncing_a_file_is_refused() {
        let dir = tempfile::tempdir().unwrap();
        let file = dir.path().join("f");
        std::fs::write(&file, b"x").unwrap();
        assert!(sync_dir(&file).is_err(), "a file must not pass as a directory");
    }

    #[test]
    fn a_durable_rename_moves_the_file() {
        let dir = tempfile::tempdir().unwrap();
        let from = dir.path().join("tmp");
        let to = dir.path().join("final");
        std::fs::write(&from, b"payload").unwrap();
        rename_durably(&from, &to).unwrap();
        assert!(!from.exists());
        assert_eq!(std::fs::read(&to).unwrap(), b"payload");
    }

    /// Overwriting is what every caller here does (`masterkey.cryptomator.tmp` over an existing
    /// key file), so it has to keep working.
    #[test]
    fn a_durable_rename_replaces_an_existing_target() {
        let dir = tempfile::tempdir().unwrap();
        let from = dir.path().join("tmp");
        let to = dir.path().join("final");
        std::fs::write(&to, b"old").unwrap();
        std::fs::write(&from, b"new").unwrap();
        rename_durably(&from, &to).unwrap();
        assert_eq!(std::fs::read(&to).unwrap(), b"new");
    }

    /// A target with no parent directory cannot be made durable, and the message has to say so
    /// rather than blame the rename.
    #[test]
    fn a_target_without_a_parent_is_an_invalid_input() {
        let dir = tempfile::tempdir().unwrap();
        let from = dir.path().join("tmp");
        std::fs::write(&from, b"x").unwrap();
        let err = rename_durably(&from, Path::new("/")).unwrap_err();
        assert_eq!(err.kind(), io::ErrorKind::InvalidInput);
    }

    /// The rename must not have happened when the source is missing -- and the error is the
    /// rename's own, not the directory sync's.
    #[test]
    fn a_missing_source_fails_before_anything_is_synced() {
        let dir = tempfile::tempdir().unwrap();
        let err = rename_durably(&dir.path().join("nope"), &dir.path().join("target")).unwrap_err();
        assert_eq!(err.kind(), io::ErrorKind::NotFound);
        assert!(!dir.path().join("target").exists());
    }
}
```

```rust
/// `fsync` on a directory, so a rename or a creation inside it survives a power cut.
///
/// A directory is opened read-only: `O_WRONLY` on a directory is `EISDIR` on Linux, and read-only
/// is enough for `fsync` on both platforms this runs on.
pub fn sync_dir(dir: &Path) -> io::Result<()> {
    let handle = std::fs::File::open(dir)?;
    // `metadata()` on the open handle rather than on the path: it cannot race with a rename, and
    // it is what makes "a file is not a directory" an error instead of a pointless fsync.
    if !handle.metadata()?.is_dir() {
        return Err(io::Error::new(
            io::ErrorKind::NotADirectory,
            format!("{} is not a directory", dir.display()),
        ));
    }
    handle.sync_all()
}

/// `rename(from, to)` plus an `fsync` on the directory holding `to`, so the new name is on the
/// platter and not only in the page cache.
///
/// Both paths are expected to be in the same directory (a temporary file next to its target,
/// which is what every caller does); only `to`'s parent is synced.
pub fn rename_durably(from: &Path, to: &Path) -> io::Result<()> {
    let parent = to.parent().ok_or_else(|| {
        io::Error::new(
            io::ErrorKind::InvalidInput,
            format!("{} has no parent directory to sync", to.display()),
        )
    })?;
    std::fs::rename(from, to)?;
    // An empty parent means `to` was relative and bare (`"x"`); the current directory is what
    // holds it then.
    sync_dir(if parent.as_os_str().is_empty() {
        Path::new(".")
    } else {
        parent
    })
}
```

```rust
///
/// Java (`MacAppleScriptMounter.mount`, webdav-nio-adapter 3.0.2) hard-codes `-s localhost` even
/// though its own server listens on `127.0.0.1`; NetAuthAgent looks the host up as the URI spells
/// it, so `host` comes from the server here instead. Everything else is Java argument for
/// argument -- including the absence of `-w`, which leaves the item's password empty and keeps
/// argv free of anything secret.
fn add_internet_password_command(host: &str, port: u16) -> Command {
    let mut command = Command::new("security");
    command
        .arg("add-internet-password")
        .args(["-a", "anonymous"])
        .args(["-s", host])
        .arg("-P")
        .arg(port.to_string())
        .args(["-r", "http"])
        .args(["-D", WEBDAV_KEYCHAIN_LABEL])
        .args(["-T", NET_AUTH_SYS_AGENT]);
    command
}

/// Best effort, exactly like Java's: a failure means macOS will ask the user about the unencrypted
/// connection, which is a nuisance rather than a broken mount. Never returns an error, and never
/// logs anything that could be a secret -- there is none in this call.
fn store_webdav_credentials(host: &str, port: u16) {
    match run_command(add_internet_password_command(host, port), CREDENTIALS_TIMEOUT) {
        // Exit 45 is `errSecDuplicateItem`: the item is already there, which is the good case on
        // every mount after the first.

        Ok(output) => log::warn!(
            "could not store the WebDAV keychain item for {host}:{port} ({}); macOS may ask about \
             the unencrypted connection: {}",

            first_line(&output.stderr)
        ),
        Err(e) => log::warn!(
            "could not run `security add-internet-password` for {host}:{port}: {e}; macOS may ask \
             about the unencrypted connection"
        ),
    }
}
```

```markdown
only ever be red is worse than none. Done by hand, on a Mac with the certificate in its keychain:

    #    notarisation requires; `--timestamp` fetches a secure timestamp (needs network).
    codesign --force --options runtime --timestamp \
      --sign "Developer ID Application: <NAME> (<TEAMID>)" crypto

    # 2. Notarisation takes an archive, not a bare binary.
    ditto -c -k --keepParent crypto crypto-notarize.zip
```

local run). Without network **only Task 4 has to be postponed**; 6 and 8 run in full, their optional

**What must not happen in any task.**
- No `git tag`, no `git push --tags`, no upload anywhere. The tag is set by the user.
- No `CRYPTO_E2E_KEYCHAIN=1`, no `CRYPTO_E2E_WEBDAV=1`, no `security` command. Task 11 builds
  the argument vector and **never** executes it.
- Install no FUSE software, no `apt`/`brew install --cask` on this machine. The
  only permitted installations are the three `cargo install` calls above.
- Create, change or delete no file under `tests/fixtures/`. The review between the tasks
  checks that with `git status --porcelain tests/fixtures/`.
- `~/.m2` and the desktop checkout are only read (Task 11, Step 1).
- No third new crate dependency. Whoever believes they need one writes in the report what for
  — and does not add it.

**What has to be in every task's report.** Besides the usual gate:
- Task 3: the actual output of `crypto --version` and of
  `CRYPTO_GIT_SHA=deadbee cargo run -q -p crypto -- --version`.
- Task 4: `ls target/man` and the first 30 lines of `man -l target/man/crypto.1`, plus the
  confirmation that there is no `crypto-__daemon.1`.
- Task 5: the unpacked tarball (`ls -R`), the output of `./crypto --version` from it and the
  result of `shasum -a 256 -c SHA256SUMS`. Explicitly also the statement that `lipo` did not
  really run.
- Task 6: the result of `ruby -c packaging/homebrew/crypto.rb`, the `cargo deb` run (or the
  reason it was skipped), and the note about the maintainer address.
- Tasks 7 and 8: the output of the Ruby structure check from Step 5, respectively the complete
  `cargo deny` output (or the reason it was skipped).
- Task 9: the runtime of `cargo test -p cryptomator-core --lib` before and after the cap — the
  test that hung before is the evidence that the problem was real.
- Task 10: the runtime of `fixtures_write` before and after the `fsync`.
- Task 11: the confirmation that `security` was **not** executed in this task, plus the
  argument vector from the test in plain text.
- Task 12: the complete output of the acceptance run from Step 6 — that is the only place where
  a human gets to see the finished package.

**After Task 12.** The branch is to be brought to `main` with
`superpowers:finishing-a-development-branch`. That completes the project; the tag `v0.1.0` and the
publishing of the draft release are the user's and are described in `docs/release.md`.
