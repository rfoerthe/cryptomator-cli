# packaging

What is here, and what is not.

| Path | Generated by | Committed? |
|---|---|---|
| `homebrew/crypto.rb` | `cargo xtask formula [--sha256-… <hex>] --write` | yes, with placeholder checksums |
| the Debian metadata | `[package.metadata.deb]` in `crates/crypto/Cargo.toml` | yes |
| manpages | `cargo xtask man` → `target/man/` | **no** (Ruling 3) |
| completion scripts | `cargo xtask completions` → `target/completions/` | **no** |
| tarballs, `SHA256SUMS`, `.deb` | `cargo xtask dist` / `cargo xtask deb` → `target/dist/` | **no** |

## The Debian package

`cargo xtask deb [--target TRIPLE] [--no-build]` builds the binary the way `cargo xtask dist` does
(`--release --locked --target …`), renders the manpages and the completion scripts into the
directories the asset list names, and then runs

```
cargo deb --manifest-path crates/crypto/Cargo.toml --target <triple> --no-build --no-strip \
          --output target/dist
```

`cargo deb` itself is not part of the workspace; install it with `cargo install cargo-deb --locked`.
Asset source paths in `[package.metadata.deb]` are resolved against `crates/crypto/`, not against
the workspace root — hence the `../../` — except for the literal prefix `target/release/`, which
cargo-deb rewrites to the real build-products directory of the selected target.

A `.deb` built on macOS contains a Mach-O binary and is good for checking the metadata only. The
package that gets published is the one the `deb` job in `release.yml` builds on Linux.

## The Homebrew formula

The committed formula's four checksums are all zeroes until a release exists, and it carries a
`# TODO: replace after the first release` line saying so — `brew install` against it cannot succeed
before then. After the first release, render the real one from the `SHA256SUMS` the workflow
attached:

```
cargo xtask formula --version 0.1.0 \
  --sha256-arm64 <hex> --sha256-x86_64 <hex> \
  --sha256-linux-arm64 <hex> --sha256-linux-x86_64 <hex> --write
```

Copying that back over `homebrew/crypto.rb` is a manual step; `docs/release.md` describes it. The
formula is checked by a test (`xtask/src/formula.rs`), which fails if the committed file is not
what the renderer produces.
